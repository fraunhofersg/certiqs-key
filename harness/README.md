# Harness

The tools, checks and role files that carry the workflow. The harness is
ordinary code: reviewed like code, tested in `tests/harness/`, and never
subject to gates, locks or lifecycles of its own (PRINCIPLES.md §7).

## The one rule

**Every tool states its motivation in its own header and in the table
below**: the concrete question it answers or the error class it catches,
ideally one that has already occurred. A tool without a written motivation is
removed. Before adding a check, a record kind or a review round, write its
cost and the error it prevents into the commit that adds it.

## Tools

For readers: [where the graphs are and how to view them](contract-reading.md).
The [core module map](../spec/module-graph.svg) and each module's graph index
are also linked from the contract PDFs and the project site.

| `contract_navigation.py` | A plain-text field (claim summary, module or group abstract) is rendered into the contract's TeX and the graph index's Markdown and read by the checker; if the three disagreed, a link or a character would work in one view and break another. It holds what they share: the escaping for TeX and Markdown, the mapped Unicode set with the TeX of each character (a character outside it stops pdflatex), the `[[label]]` link syntax and its rendering in both views, the word each claim kind prints as, and the stable PDF destinations (`claim-<id>`, `group-<id>`) that survive renumbering. Titles are projected to plain text for bookmarks and graph labels without exposing TeX commands. It also holds each kind's meta-line abbreviation ("Def. 2.1"), the `\DeclareUnicodeCharacter` lines the contract preamble generates from the whole mapped set, and the escaping of free text the checker does not read (`interface.yaml`, `spec/notation.md`), where a character outside the set prints as its code point rather than stopping pdflatex. A title's mathematics flattens through `PLAIN_TITLE_MACROS` (each mapped character's macro, a few aliases and the operator words: `$d_A\ge2$` reads d_A≥2), the one list the presentation rule `title-plain` holds titles to. | built |
| `claim_graph.py` | Human readers need the argument's shape before its details, and a hand-maintained dependency map drifts from the claims. Generates uses/assumes graphs with explicit external boundaries, reading-group overviews, focused prerequisite closures and the registry's module map; one dependency projection feeds the matrix (`overview.svg`, `overview.pdf`; the contract links the matrix and does not print it). Groups are the contract's sections as `contract_structure.contract_sections()` numbers them, so a group, section or claim number in a graph or in `graphs/README.md` is the number in the PDF; filenames derive from the section number and title, and obsolete group views are removed. Claim nodes link both the source and the rendered claim. The graph index renders module, group and claim explanations from their source metadata, with their `[[label]]` links as Markdown links into the contract PDFs, so no summary is maintained twice. The conceptual flow stays in architecture §6 and internal flowcharts in design.md. | built |
| `check_claims.py` | Kept in one file, a module's mathematics hides which claims a change reaches, so every change re-opens the whole module. With one claim per file and its edges in its header, this checks form (ids, kinds including `req`, edges, cycles, undeclared references, citations, short ids, status coherence, plain-text summaries and abstracts in the mapped Unicode set, `prominence`, no `origin` field, no bracketed title on the claim environment) and answers "what depends on this claim" so the re-review scope of a change is computed, not guessed; `--dependents` also walks `assumes` declarations and lists mentions separately. Status is local plus computed: the header `status` is a claim's local judgement and the **effective status** is the minimum over its `uses`/`assumes` closure (`--status`, `--effective`), so a claim can be accepted conditional on its dependencies without a cascade of status edits, and a module is never read as accepted while something in its closure is not. It checks the body's cross-references, because unchecked ones rot silently: `\xref{<full id>}` must name an existing, declared claim of another contract (a cross-contract reference written as a `\texttt` id would go unvalidated, and a `\ref` can resolve to a same-named local label), `[[label]]` links must resolve, every `\label` is unique in its assembled contract, `\cref` is refused (cleveref is not loaded), `\term` stands only in a definition and once per contract, `\tref` (a use of a defined term, linked to its definition) resolves to exactly one definition, since repository jargon was used pages before its definition with nothing to click, and `\repodoc` names an existing file outside the history folders. A submodule may declare sibling and foreign `depends_on` edges (checked, acyclic), so it can be deleted with exactly its dependents. The module fence applies to `uses` edges only: an `assumes` edge may name an assumption of any module, because a premise has one home and is declared wherever it is needed (reductions declares the transmitter's A-SEQ); an assumption reached that way is listed by the closure like any other. `--assumptions` prints `assumption_closure()`, the walk the claim-closure table shares. Every run adds the rules of `check_presentation.py`. An assumption carries `verification` (never or partly; `spec/claim-format.md` §3.2), required there and refused elsewhere: whether a run rests on it unverified is stated once, here, so that hand-written copies cannot disagree. An assumption may carry `category` (one value of `ASSUMPTION_CATEGORIES`), `affects` (a non-empty subset of secrecy, correctness, completeness), `refines` (another assumption's short id; the families are acyclic), `presupposes` (the roles its text presupposes, from `ASSUMPTION_PRESUPPOSITIONS`; the role-word check below) and `user_statement` (plain text under a summary's rules, at most 900 characters as rendered, its links resolved), the first four refused on other kinds; the key-rate report is built from these headers, so a value outside the vocabulary, a family naming nothing, itself, or closing a cycle, or a reading with TeX in it would otherwise surface as a broken report. `user_statement` is optional on every other kind but a definition, where it is refused (`check_user_statement`, same rules): there it is a plain reading of a result for a user who is not a proof expert, because the report shows its security statement to experimentalists and certification labs, and that reading must live with the claim it reads rather than in run-tier code that would go stale. The assumption checks below make `category`, `affects` and `user_statement` required. A definition's `assumes` is empty (a definition asserts nothing that could be false, and since an assumption may use definitions, a premise declared on a definition would let an assumption reach itself through it); the premise sits on the claims that consume it, and a `fact` keeps its hypotheses in `assumes`. `--dependents`, `--assumptions` and `--effective` accept an assumption short id wherever a claim id is accepted. The separation rules (check 13; the table below) keep apart what a contract asserts, what it points at and what binds code; they are errors of every run, each finding naming its rule as `separation[<rule>]`. `--advice` adds the editorial heuristics of `check_advice.py`, never in the default run and never in the exit code. | built |
| `check_presentation.py` | A contract is hard to read for a newcomer in ways a machine can see: prose before and after the claim environments (some of it normative), bold asides, code identifiers and file names in statements, cross-contract references as `\texttt` ids, a `\ref` resolved to the wrong local label, claim codes in titles, a duplicated title in the environment, unbounded summaries, no marker of the main results. These rules keep contracts readable, since the editor runs only on demand. Each rule is a **[presentation]** rule of `spec/claim-format.md` (prominence and summary on every claim, summary length and sentences, title length and codes, lead-in content, nothing after the proof, statement markup and code, no `\texttt` claim ids, no `\ref` into another contract, `\iface` only in requirements, module order). Run by every `check_claims`, which prints a count per rule and exits 1 on any finding (`spec/claim-format.md` §6); three of them (no `origin`, no environment title, the mapped Unicode set) are `check_claims`' own checks. Two rules serve the glossary: every `\term` carries a one-line gloss for the Terms table (`term-gloss`), and each section's first use of a multi-word defined term is a `\tref` (`term-link`; prose only, the defining section left out, single words left to the editor). `title-plain` refuses a title with a backslash outside `$...$` or a macro inside it that the plain-title map of `contract_navigation.py` does not render: titles flatten to plain text for the bookmarks, the graph labels and `graphs/README.md`, where an unmapped macro would print as raw TeX ("R\textbackslash{}'enyi"). | built |
| `check_advice.py` | Contract text a reader cannot use takes kinds a machine can point at but not judge: a very long remark, a lead-in listing dozens of claims, many pointers in one theorem's statement, `\emph{Range.}`-style headed paragraphs and "general format" second tracks inside results, sentences that inventory claims the generated meta lines already list, and statements and proofs referencing claims the header only mentions (in a proof naming an assumption, possibly an undeclared premise). Each is sometimes right, so none is a check: heuristics are never a productivity tax. `check_claims --advice [--module <id>] [--rule <name>]` prints seven heuristics (`long-statement`, `long-lead-in`, `statement-ref-mention`, `proof-ref-mention`, `statement-heading`, `general-format-track`, `inventory-sentence`; thresholds are constants in the module) and a count per rule; it is imported only under the flag, never changes the exit code, keeps no waiver or baseline file, and is run by the editor in an explicit editorial pass, never asked of a drafter. `tests/harness/test_check_advice.py` pins all of it. | built |
| `contract_structure.py` | A reader meets a claim's number in the PDF heading, the contents, the bookmarks, the claim index and the graphs; if the PDF and the graphs numbered differently, a number in one view would name nothing in the other. `contract_sections()` turns `module.yaml` into the contract's structure (Part I the core's mathematics sections, Part II its requirements in sections named after their reading group, one part per submodule, sections numbered continuously, one shared claim counter per section) with each claim's number, and both the assembler and `claim_graph.py` read it. The PDF smoke test compares every number it computes with the heading LaTeX prints. | built |
| `contract_render.py` | The body of a contract, kept apart from `assemble_contract.py`: the preamble (upright statements, one theorem counter per section, the prominence wrappers, the non-normative styles, the mapped Unicode set, the claim-body commands), the parts and sections of `contract_structure.py` with their introductions and foreign imports, and each claim as summary, numbered bookmark, lead-in, statement, generated meta line and proof. The meta line answers what a reader otherwise had to ask a tool: uses (for a requirement, what motivates it), assumes, assumed by and the ledger's machine key (read from the owner's `interface.yaml`), used by, provenance with its citation, status with the effective status when lower, code links and oracle pins. Text a claim file still carries after its statement or proof is printed, never dropped; the named destination `claim-<full id>` that other PDFs and the frontend link to is stable. A `\term` gets the named destination `term-<slug>` and a `\tref` a link to it, in this or the defining contract's PDF; the first use of each multi-word term in the overview and each section introduction is linked too. An assumption's meta line prints its `category`, `affects` and `refines` when present; every assumption gets the sentence saying whether the engine verifies it generated from `verification` (`VERIFICATION_SENTENCES`), so that no hand-written copy of that field can disagree, and its `user_statement` follows as a grey "Reading:" paragraph; any other claim carrying a `user_statement` gets the same paragraph after its statement. | built |
| `contract_frontmatter.py` | A reader wants the main results, what they assume and what the symbols mean before any section, and a way to find a claim, a defined term or an interface key after it; without them main results are unmarked, assumptions scattered and notation only in `spec/notation.md`. Writes the title page (overview, the one-line legend of the non-normative styles, links to the design notes, graphs and viewing instructions, contents), every `prominence: main` claim restated in full (labels stripped, displays tagged with their numbers) with its assumption closure, the assumptions at a glance, the notation rows the contract's bodies use, and at the back the whitelisted fields of the declared interface inputs and outputs, the numbered claim index, the index of defined terms (`\term`, makeindex) and the bibliography. The main results are listed by number, title and summary with their closures instead of restated (the digest restates them), and a Terms table follows the notation (every `\term` with its gloss, and every term of another contract the contract links with `\tref`). The assumptions table has a Category column and is grouped by category, in the vocabulary's order, once any assumption it lists carries one. | built |
| `contract_digest.py` | A contract carries every proof, remark and technical step; a reader who wants what a module states would have to read past them, and a hand-kept statements list would be a second copy that drifts. Generates `digest.tex` beside each contract: every definition, fact, assumption, result and requirement, remarks, examples, technical claims and proofs left out. Numbers are the contract's: headings print `contract_structure`'s numbers and a LaTeX guard compares each with the contract's own, read through xr-hyper from `contract.aux`, stopping the build on a difference; displays keep their numbers; a reference to anything left out links into the contract. | built |
| `contract_overview.py` | One contract PDF per core module and no page saying which results matter or in what order the modules build on each other. Generates `spec/overview/overview.tex` (the frame) and `chain.tex` (every contract's main results with their summaries and links, in module dependency order, and the module map), around the authored `spec/overview/intro.tex`; `assemble_contract --all` builds `overview.pdf`. | built |
| `assemble_contract.py` | Claims are authored one per file; a human still reads a module as one document, and a second, hand-kept copy would drift and leave a reader unsure which is the contract. Generates `contract.tex` from the claim files in the module's declared order and builds `contract.pdf`, the tracked review copy, with `latexmk`; `--check` fails when the tex or a graph view is stale or when a rendered output is missing or older than its source (by mtime for uncommitted files, by last commit for committed ones, an output also counting as current when its source is byte-identical to the source at the output's commit; a digest's `contract.tex` is compared in `aux_view`, the preamble and the ordered labels, sectioning, environments and other counter-stepping commands, which is all the digest reads through `contract.aux`, since a "Used by" or "Assumed by" line changed by another module's edit would otherwise call digests stale whose rebuild is byte-identical), and `--no-pdf` skips the PDF on a machine without TeX; `--code-url` sets the base of every code and registry link (by default the hosted repository's main branch), for a copy of the tree rendered for another host. It is the command line and the build only: it joins the body of `contract_render.py` and the front and back matter of `contract_frontmatter.py`, writes the tex, the module's statements digest (`contract_digest.py`), the graph sources and the module map, and runs latexmk (bibtex, makeindex; the digest after its contract, whose `.aux` it reads). `--all` does every core module and the overview (`contract_overview.py`) and rebuilds only what changed: a generated text is written only when its bytes differ, a render only when its `.dot` changed or the render is missing or stale (so a Graphviz upgrade never rewrites an untouched view), a PDF only when it is not current for its inputs; SVGs are written with LF, and every PDF is built with a fixed `SOURCE_DATE_EPOCH` (`FORCE_SOURCE_DATE=1`), so an unchanged source gives the same bytes and two consecutive runs leave git status unchanged. The cost is one latexmk run per rebuilt PDF; the error it prevents is a reviewer reading a PDF that is not the contract. `--all` also regenerates (`--check`: checks) the claim-closure table of `generate_claim_closure.py` where the tree ships one, because that table carries the summaries and `user_statement`s a key-rate report quotes, and the after-every-claim-change step must reach it; while check_claims reports errors it is skipped with a note. | built |
| `oracle_pins.py` | The frozen oracle registries pin claims by oracle codes (C5, PC11), never by this repository's ids, and only `tests/oracles/claim_codes.yaml` translates them; a reader asking which oracle exercises a claim had to read the table and grep the registries. Returns, per claim id, the codes mapped to it and the registry files that pin each (read as text, since `tests/` is not importable from `harness/`: a `claims`/`supports` literal, string or named constant; exactly the pins the imported walk of `test_claim_codes.py` finds), for the contract's meta line, which prints the registry files and not the codes. | built |
| `generate_bibliography.py` | Contracts cite ref-ids from `refs/index.json`, the only citable universe; the BibTeX file must be derived, never hand-maintained. | built |
| `generate_claim_closure.py` | A key rate must carry the claim graph it rests on (PRINCIPLES.md §2.1; spec/architecture.md §4.4: the claim ids of the theorem and its transitive `uses` closure), but `spec/` is not installed, so a run record cannot read the claim files. This writes `src/certiqs_key/domain/claim_closure.json`, shipped as package data: for every claim root a key-rate result may name (`certiqs_key.domain.claim_closure.CLAIM_ROOTS`), the root, its `uses` closure and its assumption short ids with their owning claims (`check_claims.assumption_closure()`, the walk `--assumptions` prints), and every module's version. The run manifest and the Frank-Wolfe result read it; `--check` fails when it is stale (`tests/harness/test_generate_claim_closure.py`). The error it prevents is a manifest naming a stale closure or a version no longer accepted; the cost is one regeneration after a claim edit, a version bump or a new root. It also lists every assumption with its owner, ledger machine key and `verification`, which the run record's never-verified marks read. The key-rate report quotes assumption text and links claims, and a run-tier copy of that text would drift from the headers: so the table also covers `ALL_ROOTS` (the result roots, the secrecy, correctness and composition roots, every device module's emission results and the completeness results; a removable submodule's emission results, `REMOVABLE_ROOTS` (for probe conditioning with the weight route read through the conditioned receiver), only while that submodule is in the tree, so that no shipped tier names them and a tree cut without it regenerates a table without them), carries each assumption's plain title, summary, `user_statement`, `category`, `presupposes` (for the run-tier role guard), `affects`, `refines`, header and effective status, generated verification sentence, contract anchor and interface emission rules, and a `claims` block with the plain title, summary and `user_statement` (null where absent; carried for every kind, since the report presents its security statement through it) for every root, limitation (`LIMITATION_CLAIMS`), cited claim (`CITED_CLAIMS`), assumption owner and every claim a carried text links to, each `[[...]]` link written as its full target. It refuses to write when a declared root, limitation or cited claim is not a claim, a link does not resolve, two assumptions share a machine key, an emission rule has a shape it cannot read, or an assumption's `verification` lies outside the package's vocabulary (`never`, `partly`; the shipped accessors refuse any other value at run time); `--check` names the top-level blocks that differ, so a table left stale by an editorial summary edit is recognisable as one. The cost is that such an edit stales the table, which `assemble_contract --all` absorbs by running the generator. | built |
| `dashboard.py` | The human entry point must be generated, not maintained: a hand-kept status page drifts. Renders `state/DASHBOARD.md` from `state/open-items/` (decisions waiting, ranked; findings by severity; tasks in order) and the claim files (the status map, with a link to each core's review PDF); `--check` fails when the checked-in page is stale. | built |
| `build_pages_site.py` and `.github/workflows/pages.yml` | A claim link must open the contract at the claim, and GitHub's file view ignores `#nameddest` while a raw PDF is downloaded, not shown; GitHub Pages serves `application/pdf`. A deploy from a branch would serve the whole tree (third-party papers in `refs/papers/`, `context/`, `state/`, `reports/`), so the tool builds the site from git through an explicit allow-list (contracts, digests, graphs, the overview, the report example pages, the BBM92 study's headline report and the whitepaper's PDF), with a deny list that wins over it and a final check of every written file against the allow-list; `latest/` is main and every tag `v*` gets its own folder, since a claim rename would otherwise break a released document's links. The workflow deploys exactly that artifact, and only after reading the Pages settings: it skips while Pages is not configured or not built by Actions, deploys to a private site built by Actions, or to a public one only where the repository variable `CERTIQS_PAGES_PUBLIC` is `true` (set in the public repository only), refuses anything else, and fails loudly if a site that should be private answers a request without credentials. `tests/harness/test_build_pages_site.py` builds the site from HEAD. | built |
| `.github/workflows/ci.yml` | Every check of this table and the default test tier otherwise run only where someone runs them, and a pull request from outside is the change least likely to have been through them. On each pull request and by hand (and on every push where the repository variable `CERTIQS_CI_PUSH_AND_NIGHTLY` is `true`, set in the public repository, so a private copy spends its minutes on pull requests alone) it runs ruff, both mypy graphs, `check_claims`, `check_symbols`, and the `--check` of the claim-closure table, the dashboard, the bibliography, the history rule and the contracts, then the default tier of `tests/harness` and `tests/unit`. The contracts' check needs neither LaTeX nor Graphviz (it compares the generated sources and judges a PDF by its commit), so the runner installs neither; tests that need them skip. Where the same variable is set, a nightly job runs the whole default tier, golden, oracle, property and integration tests included. It reads nothing a public tree leaves out, so the same file runs in the public repository. The cost is one hosted Linux job per pull request (and per push and night where enabled); the error it prevents is a change reviewed while a check it breaks is red. | built |
| `check_symbols.py` | A symbol can compile and never have been catalogued: the assembler's compile reads `spec/macros.tex`, never `spec/notation.md`, so a macro used without a catalogue row, or a part-A macro whose expansion drifted from its row, renders silently, and a symbol written as a bare letter instead of its macro (a bare `Q` for `\Qsys`) renders identically until the row moves. Reports, per claim file, a macro used that neither `spec/macros.tex` nor the file itself defines and that is not in the tool's written-out allow-list (the kernel, exactly the packages the assembler's preamble loads for claim bodies, and the claim-body commands `\xref`, `\term`, `\tref`, `\iface`, `\repodoc` and the `requirement` environment; a genuine standard command missing from it is added there, never worked around in a claim); and, per part-A macro, an expansion that differs from the one the catalogue records, read from the Macro and Rendered columns of §3's tables and the inline form of §3.9. It refuses nothing in a claim (PRINCIPLES §5), though it exits 1 on a finding; `--unused` lists macros no claim uses and is informational. Its catalogue reader also gives the contract's notation table its rows (macro and Meaning cell; `catalogue_rows`). It checks that a Meaning cell is the plain text the contract's notation table renders: no `**`/`__` emphasis ("**The** test-statistics map" would print in bold), no `§` pointer (it names a section of `spec/notation.md`, which the PDF does not hold), and no label in a code span that is not a claim name the table links (`eq:feas`, a bare `foundations/req:declared-tolerance`). | built |
| `check_history.py` | Shipped files state what is; history lives in git (PRINCIPLES.md §4). History returns with every comment written under time pressure: a decision quoted with who made it and when, a date saying when a rule arrived, a sentence about the repository this one replaced, a pointer into `reports/` or `state/`, which a reader of a published tree does not have, an email or a local path. Lists, per line of every tracked file that ships (`reports/`, `state/`, `context/`, `refs/`, `old/`, `HUMAN_SCRATCHPAD.md`, generated files and binaries left out), five categories: `attribution`, `dates`, `predecessor`, `pointers`, `identity`; a line of a claim's `notes` header is its own category, `claim-notes`, since those lines are cleaned on the editorial route. Process words (rounds, finding codes, batches) are left out: against plain words such as "effort" and "round" they read at low precision. `harness/history_allow.yaml` holds the exceptions, each with its reason and optionally a `match` that limits it to one form: `allow` (justified: layout documents, synthetic fixtures, a dataset's capture date) and `pending` (history found and not yet cleaned, file by file, counted but not failing unless `--strict`; the claim notes have none, so a history line in a claim's notes fails `--check`). `--check` exits 1 on a finding outside both lists or on an allow-list path that covers nothing, so the lists only shrink; `tests/harness/test_check_history.py` runs it on the tree. The cost is a few seconds a run and one reasoned entry per exception. | built |
| `math_diff.py` | PRINCIPLES §6's editorial route needs a tool to show that no claim statement or proof changed, so that reviewers need not word-diff by hand. On the presentational route (statements and proofs rephrased, claims split, merged, relabelled or re-kinded) a raw diff is noise from the first line (every `\ref` relabelled, every `Lemma~\ref` turned into `\xref`, a macro rename touching every formula), which is exactly where an altered hypothesis, constant or inequality direction hides. It normalises presentation away on both sides (comments, labels, reference forms resolved to full ids through the old-to-new map, macros expanded per revision, spacing, emphasis, display forms) and reports per claim and segment the tokens that still differ, labelled math or prose, with header changes (a status change flagged; an assumption's `verification` is among them, since it alone sets the run record's never-verified marks and can change with no word of the text) and text moved between claims. An assumption's `category`, `affects` and `refines` are header fields and its `user_statement` a segment like the summary, all reported and none failing, so an equivalence reviewer reading the report sees a re-categorised assumption, a changed `affects` list, a new `refines` edge or a rewritten user reading. Exit 1 when a normalised statement or proof differs or a claim is deleted or unaccounted for. It never decides equivalence: that is the equivalence reviewer's. A `\term` gloss and a `\tref`'s optional argument are dropped with the command (navigation, not mathematics). | built |
| `same_code.py` | A run record names the commit it ran at, and the study behind the whitepaper's numbers takes eight to ten hours; reusing records from an earlier tree (a rehearsal export) is sound only if the code that computed them is the code that is published, and a plain diff of the two trees buries that question under the release's comment and message edits. Compares two directories under `src`, `instances` and `runs` and lists every Python file whose syntax tree differs once docstrings are set aside, every other file that differs and every file on one side only; comment-only changes are counted. It decides nothing: a listed change that can move a recorded number means the affected runs are rerun. | built |
| `relabel.py` | Claims are renamed, re-kinded and moved. A claim id lives not only in `spec/`, which `check_claims` validates, but in code docstrings, `CLAIM_ROOTS` and the generated `claim_closure.json`, the frozen oracle registries and tests, instances and runs; there a missed id fails silently or only at a distant test. `python -m harness.relabel OLD NEW` (or `--map` for a batch) rewrites every site that provably names the claim: file, header, environment and label, `module.yaml` order and group anchors, `uses`/`mentions`/`pending`, and every reference form in claim bodies; bare labels only where they resolve in the assembled contract or the owning code package, full ids everywhere; a move across contracts turns a now-foreign `\ref` into `\xref`. What it cannot resolve safely (bare labels in tests, header notes, kind words, equation references into a moved claim, broken `depends_on` edges) it prints for repair by hand; `--dry-run` writes nothing. It never touches reports/, state/, context/, generated files, numbers or oracle codes, refuses a kind change across the proof boundary, regenerates `claim_closure.json`, and records renames, splits and merges in the cumulative map that `math_diff.py` and the frontend read. | built |
| `run_manifest` (in `domain/`) | Every result must carry its assumption ids, module versions, claim ids and tier (PRINCIPLES §2.1). Lives in `src/`, not here, but is listed because it is the one piece of the trust model the code enforces. | built |
| `runs.solver_benchmark.run`, `worker`, `summarize` | Compare candidate solvers on identical public protocol declarations, including setup, certification, failures and resource limits. Search gaps stay diagnostic; certified bounds and coverage determine practical value. Unsupported-method attribution, full warm-seed costs and alpha/key comparisons are explicit, so that downstream polish or free preprocessing cannot win the benchmark; native-effort comparisons keep the instance's iteration defaults rather than replacing them, and Clarabel's own thread pool is reported apart from the BLAS environment limits. Fast and slow profiles and explicit case/variant files make experiments reproducible without touching the proof path. See `runs/solver_benchmark/README.md`. | built |

Tree-wide tests under `tests/harness/` are checks in the sense of the rule
above and carry their motivation in their docstrings; listed here so the rule
holds. `test_claim_implements_resolve.py` resolves every claim's `implements`
field to a symbol that exists (the checker validates only the field's form
below status `implemented`, so a binding left unresolved after the code landed
would otherwise go unseen).
`test_no_predecessor_process_in_the_tree.py` refuses a shipped file that
points a reader at a governance document that does not exist here, with a
named allow-list. `test_summaries.py` additionally checks coverage of the
maintained tree: every module and group has an abstract and every non-remark
claim has a summary. This prevents new claims silently losing the reading
layer; it uses the current tree rather than a frozen count and does not judge
the prose's meaning. Its other tests cover schema errors, escaping, placement
and generated-view staleness. `test_generated_contract_rendering.py` keeps three rendering
defects out of the tracked generated files: a graphs index linking a `design.md`
heading that does not exist, `symbol: null` printed as "None" in an Interface
table, and a claim named in a Notation Meaning cell printed as typewriter text
instead of a link.
`test_emitted_claim_references.py` parses every string constant of `src/`,
`runs/` and `instances/` and resolves each claim reference in it
(`kind:label`, `module/kind:label`, equation labels) against the claim files,
and checks that a title-case kind word written before one ("Theorem
prop:rule-exact") names its kind. Refusal details, witnesses and report text
name claims as free text that reaches run records and the frontend, and a
retired or mistyped label there pointed at nothing. Emitted strings and
docstrings are separate tests; comments are not read, and whether the named
claim is the right one is a reviewer's call.

### Separation checks

The separation rules (exact checks, heuristics never a tax) keep apart what a
contract asserts, what it points at and what binds code. Each rule is
specified in `spec/claim-format.md` (marked **[separation]**, check 13, or a
presentation rule) and motivated in its tool's header. They are errors of
every run.

| Rule | Tool | Checks | Motivation | Status |
| --- | --- | --- | --- | --- |
| `statement-ref-kind` (C1) | `check_claims.py` | the statement of a theorem, lemma, proposition, corollary, definition, assumption or fact references no remark, requirement or example (`\ref`, `\eqref` or `\xref`); lead-ins, proofs and the statements of remarks, requirements and examples are not covered | statements pointed at claims they do not rest on (nineteen references in one receiver theorem), so a reader could not tell a hypothesis from a pointer; `spec/style.md` §3.4 said so in prose and nothing held it | default |
| `uses-kind` (C2) | `check_claims.py` | no theorem, lemma, proposition, corollary or definition lists a remark or a requirement in `uses` | results rested on remarks: arguments nobody had stated as a lemma, and no verifier had reviewed as one, sat in the proof closure of main results such as the compiler's gate theorem | default |
| `remark-implements` (C3) | `check_claims.py` | a remark carries no `implements`; no remark or example has status `implemented` | engine bindings lived in commentary that no requirement or result stated, ten with a note that the field "stays with this remark"; a remark has no code (`spec/style.md` §3.6) | default |
| `mention-referenced` (C6) | `check_claims.py` | every `mentions` entry is referenced in the body by `\ref`, `\eqref` or `\xref` (a summary link or a name in `notes` does not count) | `mentions` is hand-kept and had drifted, entries naming claims the body never pointed at; with check 6 the field is exact in both directions | default |
| Meaning cells plain (C4) | `check_symbols.py`, check (d) | a notation Meaning cell has no emphasis, no `§` pointer and no unlinkable label in a code span | see `check_symbols.py` above | default |
| `title-plain` (C5) | `check_presentation.py` | a title has no TeX outside `$...$` and only macros the plain-title map renders | see `check_presentation.py` above | default |

### Assumption checks

Five checks in `check_claims.py`, each specified in
`spec/claim-format.md` (§3, §3.2, §4.3, §6 checks 1, 6 and 8) and motivated
in the tool's header, plus the role-word check motivated in the same header.
They are errors of every run.

| Check | Function | Checks | Motivation | Status |
| --- | --- | --- | --- | --- |
| required fields | `check_assumption_fields` | `category`, `affects` and `user_statement` are present on every assumption (`ASSUMPTION_FIELDS_REQUIRED`) | the key-rate report is built from them, and an assumption without them rendered a blank row (five did) | default |
| body references | `check_assumption_body` | an assumption's lead-in and statement reference, by `\ref`, `\eqref` or `\xref`, only definitions, the assumption itself and the assumption its `refines` names | assumptions listed their consumers and pointed at theorems (26 references in five), so a reader could not check the condition without its consumers, and editing a consumer changed what the assumption appeared to say | default |
| `affects` against the graph | `check_affects` | an assumption in the assumption closure of a secrecy root lists `secrecy`, of a correctness root `correctness`, of a composition root at least one of the two; a root naming no claim in a module of the tree is an error. Only this direction: device premises reach the key length through a run's route, not claim edges | `affects` is hand-written, and where the graph decides it a disagreement would print a wrong "at stake" line in every report. It reads `SECRECY_ROOTS`, `CORRECTNESS_ROOTS` and `COMPOSITION_ROOTS` from `certiqs_key.domain.claim_closure`, imported inside the check as `generate_claim_closure.py` imports that module, so the run record and the check read one declaration | default |
| verification values | `check_header` | `verification` on an assumption is `never` or `partly`; `decided` and `discharged` are refused | an engine-decided condition is a definition plus a requirement and a discharged one is a lemma; these two values would let such conditions stay assumptions | default |
| unused assumptions | `check_unused_assumptions` | every assumption is declared in some claim's `assumes`, or refined by a used assumption; a superseded one is exempt (a retired assumption belongs in no closure, A-LMO) | an undeclared assumption is in no closure and no report, yet reads as a premise in the contract (A-BLOCK) | default |
| role words (check 14) | `check_role_words` | a sentence of an assumption's title (one sentence), summary or `user_statement`, as rendered, that names a role of `ROLE_WORDS` (a sender's: "her laser", "your source", "prepares"; a private setting's: "private setting", "Bob's probe") carries a `presupposes` entry satisfying that role or a word of `CONDITION_WORDS` ("where", "if", "when", "whenever", "unless", "whose", "with a trusted source", "in trusted-source mode"); `presupposes` itself is an optional list from `ASSUMPTION_PRESUPPOSITIONS` (`trusted-source`, `sends`, `setting`, `letters`), refused on other kinds | plain texts presupposed roles the run did not have: a BBM92 report, an entanglement-based run with an untrusted source and no probe, showed "her source", "her laser", "your source prepares" and "Bob's probe". The field makes the class detectable by form, and the claim-closure table carries it for the run-tier guard that refuses a run engaging a premise its roles do not satisfy. The word lists, and what they leave out and why, stand beside `ROLE_WORDS` | default |

### Staleness guards of the key-rate report

The key-rate report quotes claims through the generated closure table, so a
changed claim header reaches it on regeneration; prose written by hand that
only paraphrases a claim does not. These tests enforce that
nothing in the report goes stale when contracts change; they
are ordinary unit tests, not harness tools.

| Test | Checks | Motivation | Status |
| --- | --- | --- | --- |
| `tests/unit/test_report_paraphrase_pins.py` | a digest of the statement (read by `math_diff.parse_claim`, header excluded) of every claim that `runs/report/explain.py`'s `PARAPHRASES` or a `see` of `runs/report/glossary.yaml` names, against `tests/unit/data/report_paraphrase_pins.json`; a changed statement fails naming the prose to re-read, refreshed after re-reading with `CERTIQS_UPDATE_PARAPHRASE_PINS=1` | the report's plain-words sentences and glossary paraphrase claims by hand, and nothing regenerates them when a statement changes | default |
| `tests/unit/test_report_glossary.py` | every glossary `see` resolves to a claim file or a heading of `spec/notation.md`; every label the report emits for the committed examples is plain English or a glossary term | a renamed claim or a new label would leave the glossary pointing nowhere or a term undefined | default |

A record made by an older engine freezes its assumption texts; the report
shows the closure table's current text beside a frozen one that differs,
so that staleness is visible on the page rather than silent.

## Roles

Eight role files under `harness/roles/`, canonical; `.claude/agents/` holds
pointer stubs so Claude Code discovers them:

| Role | Does | Never |
| --- | --- | --- |
| `drafter` | writes and revises claim files and their proofs | reads a verifier's reasoning before the round; edits code |
| `verifier` | adversarially reviews a claim batch, artefacts only, different model family from the drafter | sees the drafter's brief or chat; edits anything |
| `implementer` | derives interface and code from accepted claims, plans before coding; maintains implementation bindings and non-normative summaries | changes mathematical claim bodies or statuses; invents an assumption to avoid an amendment |
| `implementation-verifier` | reviews code and tests against the accepted claims, proposes tests as diffs | edits code |
| `editor` | rewrites contracts for readability on the presentational route, on demand (`spec/style.md`) | changes mathematics; fixes a suspected error instead of reporting it |
| `equivalence-reviewer` | certifies, artefacts only, that a presentational rewrite changed no mathematics | sees the editor's reasoning; edits anything |
| `cold-reader` | reads one rendered section as a QKD theorist new to the repository and reports where it breaks | judges correctness; reads beyond the section |
| `report-reader` | reads a rendered key-rate report as an experimentalist or a certification lab, answers a fixed quiz and reports where it breaks; the report's authors know every label and cannot judge this themselves | judges correctness; reads outside the report folder |

Human acts (`accept`, `accept-implementation`) are recorded by the commit
that applies them, with the trailer `Decided-by: <maintainer's name>` (PRINCIPLES.md §2.4).
No role writes that trailer on its own.

## Environment

The environment and the checks CI runs are set up as the top-level
[README](../README.md#development) says.

The two mypy commands cover `src/`, `instances/` and `runs/`, and they are two
commands because they are two import graphs. `mypy src instances runs`
replaces `mypy src`, which does not see `instances/` at all: with it nothing
under `instances/` or `runs/` would be type-checked by any gate, so a
re-export error in an instance would be invisible to every green run. That is
the error class the second command catches.

`-o addopts=""` drops the coverage and import-mode flags of `pyproject.toml`
so the summary line is printed once. The QICS oracle extra
(`.[oracle-qics]`) is optional on purpose; tests that need it carry the
`requires_qics` marker.

The known traps of this environment (CRLF written by Python, YAML quoting,
backslashes through the shell, transient reds when several agents share one
clone, PDF freshness) are in [PITFALLS.md](PITFALLS.md), a note rather than a
tool.
