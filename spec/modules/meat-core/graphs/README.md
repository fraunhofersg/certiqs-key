## Module summary

Summaries explain purpose and content. They are non-normative; the claim statements, proofs and declared assumptions remain authoritative.

**Non-normative summary.** The MEAT core of the key\-rate engine \(the module meat\-core\) turns a finite protocol declaration, which the protocol compiler emits, and an acceptance set into a convex entropy program and a fixed\-length key length; four of its main results form one chain from the single\-round protocol channel the declaration generates to that key length, and the fifth is the security of the protocol that outputs it \([Corollary “Security of the protocol and its net key”](../contract.pdf#nameddest=claim-meat-core/cor:composed-security)\)\. Marginal\-constrained entropy accumulation bounds the entropy of the accepted raw key from below by n times a single\-round rate, less a penalty in the acceptance probability, against every adaptive attack with a finite\-dimensional quantum memory \([Theorem “Accumulated entropy bound under adaptive attacks”](../contract.pdf#nameddest=claim-meat-core/thm:accumulated-entropy)\)\. A licensed constraint list, one whose entries have a type the declared source mode admits, raises that rate only under the attack\-set licence, the producer's certificate that every physical attack reduces to one that respects the list\. The single\-round rate is bounded below by the value h\_low \(written as an underlined h\_α\) of a finite convex program over sector\-block states \([Theorem “Reduction of the rate to the convex program”](../contract.pdf#nameddest=claim-meat-core/thm:reduction)\), which a Choi parametrisation writes in solver\-friendly variables without deciding the rank of Alice's marginal\. The objective at any feasible point is an upper estimate of h\_low, never a lower bound on it \([Lemma “Upper estimate of the value at any feasible point”](../contract.pdf#nameddest=claim-meat-core/lem:estimate)\), while any lower bound on h\_low, however obtained, yields a key length \([Corollary “Key length from any lower bound on the value”](../contract.pdf#nameddest=claim-meat-core/cor:keylength-bound)\) through the fixed\-length post\-processing model: the key is secret \([Theorem “Secrecy of the key from the accumulated entropy”](../contract.pdf#nameddest=claim-meat-core/thm:keylength)\) and correct, and over an authentication scheme the protocol is secure with the authentication error added and its key consumption subtracted \([Corollary “Security of the protocol and its net key”](../contract.pdf#nameddest=claim-meat-core/cor:composed-security)\), against an adversary whose memory has any dimension\. In trusted\-source mode Alice's marginal is fixed, which needs the source licence of the transmitter module, the attestation that her system never reaches the adversary; untrusted\-source mode leaves it free and never gives a larger value\. The Frank\-Wolfe submodule supplies the first\-order lower bound on h\_low, with both linear minima bounded exactly, evaluates it, where the chain carries one, on the reference companion, the declaration of the reference model compiled beside the snapped one, and certifies it where every step from the declaration's data can be enclosed rigorously\. The module admits declared data only when they are exactly admissible, the companion aside, which it admits beside its declaration and searches only in a short polish from the declaration's points; it characterises no device and constructs no honest statistics, and only the submodule's certified evaluation bounds the rounding of a computed number; where the honest statistics are supplied rather than computed from the declared devices, or the caller declares a constraint entry, it bounds the mismatch between the acceptance set and the feasible statistics from below, records the cap this proves on the probability that devices as declared pass the acceptance test, and refuses the run where that cap is at most a threshold, one half by default\.

## Part I: Mathematics

### 1 The declaration and the protocol channel

[Dependency view](group-01-the-declaration-and-the-protocol-channel.svg)

**Non-normative summary.** This section fixes the data every later result is computed from and the channel those data generate\. The protocol declaration is the compiler's, read here with the conditions and names this module's claims rest on \([Definition “The protocol declaration as the MEAT core reads it”](../contract.pdf#nameddest=claim-meat-core/def:declaration)\); an ensemble\-form declaration denotes an ordinary one \([Lemma “The measurement an ensemble\-form declaration denotes”](../contract.pdf#nameddest=claim-meat-core/lem:ensemble-form)\)\. From the declared measurements, announcements and key map the module generates a single\-round protocol channel whose acceptance marginal is the statistics map \([Theorem “The declaration generates a protocol channel”](../contract.pdf#nameddest=claim-meat-core/thm:protocol-channel)\), and branch maps that split the announcement classes of each acceptance value into pass and fail classes \([Definition “Branch maps”](../contract.pdf#nameddest=claim-meat-core/def:branch), [Lemma “Properties of the pass and fail branch maps”](../contract.pdf#nameddest=claim-meat-core/lem:branch-maps)\)\. The branch maps carry the orthogonality the entropy calculation uses, and a component of a register other than the raw\-key register that is constant across a branch map's Kraus terms can be removed from it without changing any quantity of this module \([Remark “Inert register components of a branch map”](../contract.pdf#nameddest=claim-meat-core/rem:inert)\)\.

- 1.1 [`meat-core/def:declaration`](../claims/def-declaration.tex): The protocol declaration as the MEAT core reads it ([PDF](../contract.pdf#nameddest=claim-meat-core/def:declaration))

  **Non-normative summary.** The declaration is the compiler's \([Definition “Protocol declaration”](../../protocol-compiler/contract.pdf#nameddest=claim-protocol-compiler/def:declaration)\), in either format, admissible \([Definition “Admissible declaration”](../contract.pdf#nameddest=claim-meat-core/def:admissible-declaration)\), sifting by the announcements and a raw key its holder can compute\. This module adds the key\-live acceptance values, its reading of the party partition, the summation order and exact admissibility\.

- 1.2 [`meat-core/def:admissible-declaration`](../claims/def-admissible-declaration.tex): Admissible declaration ([PDF](../contract.pdf#nameddest=claim-meat-core/def:admissible-declaration))

  **Non-normative summary.** An admissible declaration is finite with total maps, a well\-formed marginal slot, block\-diagonal POVMs, announcement\-determined sifting, constraints typed by the source mode and a non\-empty feasible set\. Each party announces from its own readout and the key holder computes the raw key from its own\.

- 1.3 [`meat-core/lem:ensemble-form`](../claims/lem-ensemble-form.tex): The measurement an ensemble-form declaration denotes ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:ensemble-form))

  **Non-normative summary.** Positive operators summing to Alice's marginal sector by sector denote a POVM, block diagonal along her sectors, that returns them between square roots of the marginal and vanishes on a sector exactly where they do\. Conversely a POVM and a marginal, both block diagonal, give such operators\.

- 1.4 [`meat-core/def:maps`](../claims/def-maps.tex): Generated registers, isometries and maps ([PDF](../contract.pdf#nameddest=claim-meat-core/def:maps))

  **Non-normative summary.** The declaration generates coherent measurement, announcement, statistic and key isometries, the single\-round protocol map, the key pinching and the statistics map\. They give the entropy proof a precise representation of the protocol's classical outputs\.

- 1.5 [`meat-core/thm:protocol-channel`](../claims/thm-protocol-channel.tex): The declaration generates a protocol channel ([PDF](../contract.pdf#nameddest=claim-meat-core/thm:protocol-channel))

  **Non-normative summary.** For an admissible declaration \([Definition “Admissible declaration”](../contract.pdf#nameddest=claim-meat-core/def:admissible-declaration)\) the single\-round protocol map is a channel with classical key, acceptance and announcement registers, given by an explicit measurement formula\. Its acceptance marginal is exactly the statistics map\.

- 1.6 [`meat-core/def:branch`](../claims/def-branch.tex): Branch maps ([PDF](../contract.pdf#nameddest=claim-meat-core/def:branch))

  **Non-normative summary.** Each acceptance value splits its announcement classes into pass and fail classes, and the two branch maps sum the Kraus terms of each, sector by sector as well\. They keep the coherence the entropy calculation needs while separating key\-bearing rounds from discarded ones\.

- 1.7 [`meat-core/lem:branch-maps`](../claims/lem-branch-maps.tex): Properties of the pass and fail branch maps ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:branch-maps))

  **Non-normative summary.** The pass and fail maps are trace\-non\-increasing, their traces add up to the acceptance value's probability, their outputs have orthogonal supports and the fail branch is fixed by the key pinching\. They split by sector on block\-diagonal inputs, and a value that is not key\-live has a zero pass map\.

- 1.8 [`meat-core/rem:inert`](../claims/rem-inert.tex): Inert register components of a branch map ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:inert))

  **Non-normative summary.** An isometry on registers other than the raw\-key register leaves the pinched trace power unchanged, so no quantity of this module depends on a component of another register that is constant across a branch map's Kraus terms\. Varying components and the raw\-key register carry what the proofs use\.


### 2 Accumulation

[Dependency view](group-02-accumulation.svg)

**Non-normative summary.** The imported sequential accumulation theorem bounds the entropy of an accepted multi\-round state from below by the round count times a single\-round rate, less a penalty in the acceptance probability \([Fact “Marginal\-constrained entropy accumulation, sequential form”](../contract.pdf#nameddest=claim-meat-core/fact:meat)\)\. Instantiated on the generated round channels, with every announcement handed to the adversary and her quantum memory carried between rounds, it gives the section's main result, [Theorem “Accumulated entropy bound under adaptive attacks”](../contract.pdf#nameddest=claim-meat-core/thm:accumulated-entropy): on acceptance, the entropy of the raw key given the adversary's information is at least n times the single\-round rate less \(α/\(α−1\)\)·log₂\(1/Pr\[accept\]\), with the product marginal of Alice's systems in trusted\-source mode derived from the source's premises, A\-SEED \(v\) and A\-LAB at the party holding A \([Lemma “Product marginal of Alice's retained systems”](../contract.pdf#nameddest=claim-meat-core/lem:product-marginal)\), and with no source assumption in untrusted\-source mode\. Licensed constraint lists, licensed attack sets and the constrained single\-round rate are defined here; a constraint list may raise the rate only through a licensed restriction of the attack model \([Remark “Where declared constraints may enter the rate”](../contract.pdf#nameddest=claim-meat-core/rem:no-constraints)\)\.

- 2.1 [`meat-core/fact:meat`](../claims/fact-meat.tex): Marginal-constrained entropy accumulation, sequential form ([PDF](../contract.pdf#nameddest=claim-meat-core/fact:meat))

  **Non-normative summary.** On an accepted event the Rényi entropy of n rounds of sequential channels with quantum memory, under a product marginal constraint, is at least n times a single\-round rate less \(α/\(α−1\)\)·log₂\(1/p\_Ω\)\. The rate minimises a KL penalty plus conditional entropies over the channels' convex range\.

- 2.2 [`meat-core/def:homog`](../claims/def-homog.tex): Licensed constraint list and its two classes ([PDF](../contract.pdf#nameddest=claim-meat-core/def:homog))

  **Non-normative summary.** A constraint list is licensed when it is licensed for the declared source mode in the sense of [Definition “Licensed constraint list”](../../protocol-compiler/contract.pdf#nameddest=claim-protocol-compiler/def:homog), a type check that compares no numbers\. Its classes are τ\_A\-homogeneous lists in trusted mode and scalar lists in untrusted mode; the general format adds party\-local entries\.

- 2.3 [`meat-core/def:roundmodel`](../claims/def-roundmodel.tex): Round model and licensed attack sets ([PDF](../contract.pdf#nameddest=claim-meat-core/def:roundmodel))

  **Non-normative summary.** The round model is that of foundations at the squashed system, with round channels that hand every public announcement to the adversary's memory\. A licensed attack set bounds each attack's adjoint by the declared constraints; whether a protocol reduces to it is the attack\-set licence\.

- 2.4 [`meat-core/def:hqkd-list`](../claims/def-hqkd-list.tex): Constrained target set and single-round rate ([PDF](../contract.pdf#nameddest=claim-meat-core/def:hqkd-list))

  **Non-normative summary.** The constrained single\-round rate minimises a KL penalty plus the key's conditional entropy over acceptance distributions and states meeting the declared marginal and constraint list; at the empty list it is the unconstrained rate\. Constraints only raise it, so using it needs a licence\.

- 2.5 [`meat-core/def:admissible-acceptance-set`](../claims/def-admissible-acceptance-set.tex): Admissible acceptance set ([PDF](../contract.pdf#nameddest=claim-meat-core/def:admissible-acceptance-set))

  **Non-normative summary.** An acceptance set is admissible when it is a closed convex subset of the probability simplex on the acceptance values\. Accumulation, the attainment and limit results and the first\-order bound all read that geometry\.

- 2.6 [`meat-core/lem:cond-more`](../claims/lem-cond-more.tex): Conditioning on more side information ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:cond-more))

  **Non-normative summary.** The sandwiched conditional Rényi entropy cannot increase when the conditioning system grows, by data processing under the partial trace\. The conservative steps that hand the adversary extra information rest on it\.

- 2.7 [`meat-core/lem:purifier-indep`](../claims/lem-purifier-indep.tex): Independence of the purifier size ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:purifier-indep))

  **Non-normative summary.** Once the adversary's register is at least as large as Alice's and the measured system together, enlarging it leaves the constrained single\-round rate unchanged\. The inner infimum may be restricted to pure states, which the branch formula uses\.

- 2.8 [`meat-core/lem:range`](../claims/lem-range.tex): Constraint transport and range inclusion ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:range))

  **Non-normative summary.** An admissible attack carries the licensed bounds on its adjoint over to the constraint conditions on the round's state, so every round output lies in the constrained target set\. A larger output set can only lower the rate, which is the conservative comparison accumulation needs\.

- 2.9 [`meat-core/lem:product-marginal`](../claims/lem-product-marginal.tex): Product marginal of Alice's retained systems ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:product-marginal))

  **Non-normative summary.** In trusted\-source mode, under retention, emission of the specified ensemble, sequential rounds, private source randomness and a sealed laboratory, the n rounds start with Alice's systems in the declared marginal in product, and each round finds her system in that marginal\.

- 2.10 [`meat-core/thm:accumulated-entropy`](../claims/thm-accumulated-entropy.tex): Accumulated entropy bound under adaptive attacks ([PDF](../contract.pdf#nameddest=claim-meat-core/thm:accumulated-entropy))

  **Non-normative summary.** On acceptance, the raw key's Rényi entropy given the adversary's information is at least n times the single\-round rate less α/\(α−1\)·log₂\(1/Pr\[accept\]\), for any adaptive attack with a finite\-dimensional memory\. Trusted\-source mode reads the product marginal of [Lemma “Product marginal of Alice's retained systems”](../contract.pdf#nameddest=claim-meat-core/lem:product-marginal); untrusted mode needs none\.

- 2.11 [`meat-core/rem:accumulation-scope`](../claims/rem-accumulation-scope.tex): Scope of the accumulated entropy bound ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:accumulation-scope))

  **Non-normative summary.** The bound of [Theorem “Accumulated entropy bound under adaptive attacks”](../contract.pdf#nameddest=claim-meat-core/thm:accumulated-entropy) covers adaptive attacks with a finite\-dimensional memory of any size, the tensor\-product state model being a special case\. In untrusted\-source mode it holds with a smaller single\-round rate, the price of not assuming a trusted source\.

- 2.12 [`meat-core/rem:no-constraints`](../claims/rem-no-constraints.tex): Where declared constraints may enter the rate ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:no-constraints))

  **Non-normative summary.** The imported theorem fixes the inner infimum over the outputs of all attacks, so a constraint list may raise the rate only through a licensed restriction of the attack model \([Theorem “Constrained accumulation under the attack\-set licence”](../contract.pdf#nameddest=claim-meat-core/thm:constrained-accumulation)\)\. Device knowledge without such a licence enters through the declared measurement\.


### 3 Constrained accumulation

[Dependency view](group-03-constrained-accumulation.svg)

**Non-normative summary.** When the reduction chain behind the declaration restricts every attack to a licensed attack set, the accumulated entropy bound holds with the constrained single\-round rate of the declared list, with the same penalty \([Theorem “Constrained accumulation under the attack\-set licence”](../contract.pdf#nameddest=claim-meat-core/thm:constrained-accumulation)\)\. The licensed class is the one the licence transports and not an arbitrary choice: multiples of τ\_A in trusted\-source mode and scalars in untrusted\-source mode \([Remark “Canonicity of the licensed class”](../contract.pdf#nameddest=claim-meat-core/rem:homog)\), a trusted\-mode entry declaring the scalar so that no numerical test is needed \([Remark “Scalar declaration of a homogeneous right\-hand side”](../contract.pdf#nameddest=claim-meat-core/rem:scalar-declaration)\)\. For a party\-local entry of the general format the theorem stays true, though that reading is not shown canonical \([Remark “Party\-local entries and constrained accumulation”](../contract.pdf#nameddest=claim-meat-core/rem:tagged-entries-and-accumulation)\)\. The published flag\-state squasher is an instance \([Example “The flag\-state squasher as a licensed constraint list”](../contract.pdf#nameddest=claim-meat-core/ex:fss)\), and [Remark “Limits of the attack\-set licence”](../contract.pdf#nameddest=claim-meat-core/rem:not-licensed) records what the licence does not cover\.

  **Non-normative summary.** Under the attack\-set licence [A\-ATK](../../protocol-compiler/contract.pdf#nameddest=claim-protocol-compiler/ass:atk), the accumulated entropy bound holds with the constrained single\-round rate of a licensed list in place of the unconstrained rate, with the same acceptance\-probability penalty\. The constrained rate is never below the unconstrained one\.

- 3.2 [`meat-core/rem:tagged-entries-and-accumulation`](../claims/rem-tagged-entries-and-accumulation.tex): Party-local entries and constrained accumulation ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:tagged-entries-and-accumulation))

  **Non-normative summary.** No statement of the constrained accumulation theorem becomes false for a list with a party\-local entry: its hypotheses are satisfiable, its conclusion holds and its monotonicity survives\. - 3.3 [`meat-core/ex:fss`](../claims/ex-fss.tex): The flag-state squasher as a licensed constraint list ([PDF](../contract.pdf#nameddest=claim-meat-core/ex:fss))

  **Non-normative summary.** The restricted attack set of the published flag\-state squasher is exactly the attack set of one licensed entry, a designated outcome's element minus λ\_min times the flag projector bounded below by 0, in either source mode\. - 3.4 [`meat-core/rem:homog`](../claims/rem-homog.tex): Canonicity of the licensed class ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:homog))

  **Non-normative summary.** The licence transports exactly τ\_A\-multiples in trusted mode and scalars in untrusted mode, where the operator form c\_k·1\_A can empty the feasible set\. ### 4 Branch entropy and sectors

[Dependency view](group-04-branch-entropy-and-sectors.svg)

**Non-normative summary.** A pure input's conditional entropy on one acceptance value is a function of the protocol marginal alone, through the ratio of a pinched trace\-power quantity to the outcome probability, and that quantity splits into sector deficits on block\-diagonal inputs \([Theorem “Branch entropy from the protocol marginal”](../contract.pdf#nameddest=claim-meat-core/thm:branch-formula)\)\. The pinched trace power is concave on the whole positive cone \([Lemma “Concavity on the positive cone”](../contract.pdf#nameddest=claim-meat-core/lem:cone-concavity)\), and every sector deficit is non\-positive \([Corollary “Non\-positivity of the sector deficits”](../contract.pdf#nameddest=claim-meat-core/cor:f-nonpos)\) and vanishes on a key\-inert pair, whose variables still enter the statistics \([Proposition “Exact cancellation of key\-inert sectors”](../contract.pdf#nameddest=claim-meat-core/prop:exact-cancellation)\)\. With Alice sectors the same holds per joint sector \([Lemma “The objective split over joint sectors”](../contract.pdf#nameddest=claim-meat-core/lem:joint-sectors)\)\.

- 4.1 [`meat-core/thm:branch-formula`](../claims/thm-branch-formula.tex): Branch entropy from the protocol marginal ([PDF](../contract.pdf#nameddest=claim-meat-core/thm:branch-formula))

  **Non-normative summary.** A pure input's conditional entropy on one acceptance value is 1/\(1−α\) times log₂ of K/P, the ratio of a pinched trace\-power quantity K to the outcome probability P, and K splits into sector deficits on block\-diagonal inputs\. The bounds 0 ≤ K ≤ P hold on the whole positive cone\.

- 4.2 [`meat-core/cor:concavity`](../claims/cor-concavity.tex): Concavity of the branch quantities on subnormalised states ([PDF](../contract.pdf#nameddest=claim-meat-core/cor:concavity))

  **Non-normative summary.** For α \> 1 the pinched trace power is concave on subnormalised operators, so every sector deficit is concave on subnormalised sector states and each K is concave on the feasible set\. It is the imported concavity result read at the parameter 1/α\.

- 4.3 [`meat-core/lem:cone-concavity`](../claims/lem-cone-concavity.tex): Concavity on the positive cone ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:cone-concavity))

  **Non-normative summary.** The pinched trace\-power functional T is positively homogeneous and concave on the whole positive cone\. Hence the sector deficits are concave on the cone and the branch quantities K on its sector\-block\-diagonal part, for every block\-diagonal positive measurement family, complete or not\.

- 4.4 [`meat-core/cor:f-nonpos`](../claims/cor-f-nonpos.tex): Non-positivity of the sector deficits ([PDF](../contract.pdf#nameddest=claim-meat-core/cor:f-nonpos))

  **Non-normative summary.** Every sector deficit is non\-positive on the whole positive cone, with no trace hypothesis, and vanishes exactly when its passing\-branch output is block\-diagonal for the key pinching\. [Proposition “Exact cancellation of key\-inert sectors”](../contract.pdf#nameddest=claim-meat-core/prop:exact-cancellation) reads the equality case\.

- 4.5 [`meat-core/def:keyinert`](../claims/def-keyinert.tex): Key-inert pair ([PDF](../contract.pdf#nameddest=claim-meat-core/def:keyinert))

  **Non-normative summary.** A key\-live acceptance value and a sector form a key\-inert pair when the raw key is constant on the effective outcomes of each passing announcement class\. The predicate is finite and read off the declaration, and it marks the pairs whose deficit cancels exactly \([Proposition “Exact cancellation of key\-inert sectors”](../contract.pdf#nameddest=claim-meat-core/prop:exact-cancellation)\)\.

- 4.6 [`meat-core/prop:exact-cancellation`](../claims/prop-exact-cancellation.tex): Exact cancellation of key-inert sectors ([PDF](../contract.pdf#nameddest=claim-meat-core/prop:exact-cancellation))

  **Non-normative summary.** On a key\-inert pair the sector deficit vanishes for every positive input, so the sector contributes nothing to the entropy term\. Its variables still enter the outcome probabilities, the statistics and the marginal constraint\.

- 4.7 [`meat-core/def:keyactive`](../claims/def-keyactive.tex): Key-active index set ([PDF](../contract.pdf#nameddest=claim-meat-core/def:keyactive))

  **Non-normative summary.** The key\-active index set of an acceptance value holds the sectors that are not key\-inert with it\. Restricting the deficit sum to it leaves the objective exactly equal, not bounded, and removes no state variable\.

- 4.8 [`meat-core/def:joint-sectors`](../claims/def-joint-sectors.tex): Joint-sector deficits and the joint key-active index set ([PDF](../contract.pdf#nameddest=claim-meat-core/def:joint-sectors))

  **Non-normative summary.** With Alice sectors, the branch maps, statistics and deficit restrict to each joint sector, and a joint pair is key\-inert when the raw key is constant on the outcomes that can occur on it, decided on declared data\. With one Alice sector these are the sector notions\.

- 4.9 [`meat-core/lem:joint-sectors`](../claims/lem-joint-sectors.tex): The objective split over joint sectors ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:joint-sectors))

  **Non-normative summary.** On states block\-diagonal along Alice's and the measured sectors, the branch maps, the statistics and K split per joint sector; each deficit is non\-positive, concave and positively homogeneous\. Key\-inert joint pairs add zero, so the sum may be restricted to the joint key\-active index set\.


### 5 The program and its reduction

[Dependency view](group-05-the-program-and-its-reduction.svg)

**Non-normative summary.** The feasible set, the objective and its infimum h\_low over the acceptance set form the finite convex program of this module; at d\_A = 1 the two source modes give the same program \([Proposition “The two source modes coincide at a trivial Alice system”](../contract.pdf#nameddest=claim-meat-core/prop:trivial-alice-system)\), and untrusted\-source mode never gives a larger value\. The section's main result, [Theorem “Reduction of the rate to the convex program”](../contract.pdf#nameddest=claim-meat-core/thm:reduction), shows that h\_low bounds the single\-round rate from below for an unconstrained declaration in either source mode, every step being an equality or conservative, and [Corollary “The reduction for arbitrary constraint lists”](../contract.pdf#nameddest=claim-meat-core/cor:reduction-constrained) extends it to arbitrary constraint lists\. Restricting the variable along Alice's sectors changes no value \([Proposition “Value neutrality along Alice's sectors”](../contract.pdf#nameddest=claim-meat-core/prop:a-neutral)\)\. The value lies in \[0, \+∞\], each entropy term being at most log₂\(d\_Z \+ 1\) while the divergence penalty is unbounded \([Proposition “Range of the value and its finite entropy part”](../contract.pdf#nameddest=claim-meat-core/prop:value-range)\), and an infinite value means that no attack the declared list admits is accepted \([Remark “Reading an infinite value”](../contract.pdf#nameddest=claim-meat-core/rem:hlow-range)\)\. The objective is jointly convex and lower semicontinuous, so a finite infimum is attained \([Theorem “Joint convexity of the program”](../contract.pdf#nameddest=claim-meat-core/thm:convexity)\)\.

- 5.1 [`meat-core/def:feasible`](../claims/def-feasible.tex): Feasible set and computable objective ([PDF](../contract.pdf#nameddest=claim-meat-core/def:feasible))

  **Non-normative summary.** The program minimises an entropy objective over the compiler's feasible set \([Definition “Feasible set”](../../protocol-compiler/contract.pdf#nameddest=claim-protocol-compiler/def:feasible)\), read as normalised block\-diagonal states meeting the declared marginal and constraints\. Its infimum over the acceptance set, h\_low, is the value a key length is computed from\.

- 5.2 [`meat-core/prop:trivial-alice-system`](../claims/prop-trivial-alice-system.tex): The two source modes coincide at a trivial Alice system ([PDF](../contract.pdf#nameddest=claim-meat-core/prop:trivial-alice-system))

  **Non-normative summary.** At d\_A = 1 the two source modes have the same feasible set, the n\-round product\-marginal condition holds for every normalised state, the two licensed constraint classes coincide and the source licence deletes no attack\. The two modes are then one declaration\.

- 5.3 [`meat-core/rem:modes-da1`](../claims/rem-modes-da1.tex): The two source modes on the program ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:modes-da1))

  **Non-normative summary.** A declared marginal deletes every feasible state with another marginal, so untrusted\-source mode is always available and never gives a larger value\. At d\_A = 1 the two modes coincide, which lets a protocol with no trusted source be declared there; τ\_A = 0 is inadmissible\.

- 5.4 [`meat-core/thm:reduction`](../claims/thm-reduction.tex): Reduction of the rate to the convex program ([PDF](../contract.pdf#nameddest=claim-meat-core/thm:reduction))

  **Non-normative summary.** For a declaration that adds no constraints on the state \(an empty constraint list\), in either source mode, the value h\_low of the finite convex program bounds the single\-round rate from below\. Every step of the reduction is an equality or lowers the bound, so the computable program is conservative\.

- 5.5 [`meat-core/prop:a-neutral`](../claims/prop-a-neutral.tex): Value neutrality along Alice's sectors ([PDF](../contract.pdf#nameddest=claim-meat-core/prop:a-neutral))

  **Non-normative summary.** Pinching a feasible state along Alice's declared sectors keeps it feasible with the same statistics and an objective no larger\. So restricting the variable to states block diagonal there changes no value, and the pinching carries minimisers to minimisers\.

- 5.6 [`meat-core/cor:reduction-constrained`](../claims/cor-reduction-constrained.tex): The reduction for arbitrary constraint lists ([PDF](../contract.pdf#nameddest=claim-meat-core/cor:reduction-constrained))

  **Non-normative summary.** For any declared constraint list, licensed or not, the constrained value bounds the constrained single\-round rate from below, with the same list on both sides\. A key length from the constrained value still needs the attack\-set licence of [Theorem “Constrained accumulation under the attack\-set licence”](../contract.pdf#nameddest=claim-meat-core/thm:constrained-accumulation)\.

- 5.7 [`meat-core/rem:losses`](../claims/rem-losses.tex): Where each step of the reduction loses ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:losses))

  **Non-normative summary.** The divergence term passes through the reduction as an identity, purification loses nothing when the optimum is attained on pure states, and the arrow replacement's gap closes as α → 1\. No step reverses direction\.

- 5.8 [`meat-core/prop:value-range`](../claims/prop-value-range.tex): Range of the value and its finite entropy part ([PDF](../contract.pdf#nameddest=claim-meat-core/prop:value-range))

  **Non-normative summary.** The objective is non\-negative on the feasible set, so h\_low lies in \[0, \+∞\]; each entropy term is at most log₂\(d\_Z \+ 1\), while the divergence penalty has no finite bound\. If h\_low = \+∞, no accepted distribution is absolutely continuous with respect to the statistics of a feasible state\.

- 5.9 [`meat-core/rem:hlow-range`](../claims/rem-hlow-range.tex): Reading an infinite value ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:hlow-range))

  **Non-normative summary.** An infinite value of the program is the infeasibility of the declared acceptance set against the declaration: no attack the declared list admits is then accepted and no key is produced\. The entropy part of the objective is capped, the divergence penalty is not\.

- 5.10 [`meat-core/thm:convexity`](../claims/thm-convexity.tex): Joint convexity of the program ([PDF](../contract.pdf#nameddest=claim-meat-core/thm:convexity))

  **Non-normative summary.** The objective is jointly convex and lower semicontinuous in the acceptance distribution and the feasible state, so h\_low is a convex minimisation over a compact convex set\. A finite infimum is attained\.


### 6 Sector classes and sector removal

[Dependency view](group-06-sector-classes-and-sector-removal.svg)

**Non-normative summary.** Sectors are classified by exact predicates on the declared data as key\-active, constraint\-active, state\-blind and removable, removability being certified, for a list without party\-local entries, by an exhibited witness that meets a six\-condition checklist \([Definition “Sector classes and the removal checklist”](../contract.pdf#nameddest=claim-meat-core/def:classes)\)\. A state\-blind sector may be deleted when a mixture of states on distinct other key\-inert sectors reproduces its responses and constraint values \([Theorem “Sound removal of a state\-blind sector”](../contract.pdf#nameddest=claim-meat-core/thm:removal)\), and a set of such sectors when every witness targets only sectors that stay \([Proposition “Deleting a set of removable sectors”](../contract.pdf#nameddest=claim-meat-core/prop:removal-compose)\)\. Dropping a constraint\-active sector \([Proposition “Unsoundness of dropping a constraint\-active sector”](../contract.pdf#nameddest=claim-meat-core/prop:retention)\) or averaging sectors \([Proposition “Unsoundness of averaging sectors”](../contract.pdf#nameddest=claim-meat-core/prop:no-averaging)\) can overstate the key\. The remarks show why the index conditions of the checklist are needed, why the witness must be exact, and that a tolerance may only refuse a removal\.

- 6.1 [`meat-core/def:classes`](../claims/def-classes.tex): Sector classes and the removal checklist ([PDF](../contract.pdf#nameddest=claim-meat-core/def:classes))

  **Non-normative summary.** Exact predicates on the declared data make a sector key\-active, constraint\-active, state\-blind or removable; for a list without party\-local entries, removability is certified by a witness meeting a six\-condition checklist\. Deleting several removable sectors needs a further condition on the set\.

- 6.2 [`meat-core/thm:removal`](../claims/thm-removal.tex): Sound removal of a state-blind sector ([PDF](../contract.pdf#nameddest=claim-meat-core/thm:removal))

  **Non-normative summary.** A state\-blind sector may be deleted when a mixture of states on distinct other sectors, all key\-inert, reproduces its responses and its constraint values\. Deleting it changes neither the value of the program nor its attainment\.

- 6.3 [`meat-core/prop:retention`](../claims/prop-retention.tex): Unsoundness of dropping a constraint-active sector ([PDF](../contract.pdf#nameddest=claim-meat-core/prop:retention))

  **Non-normative summary.** A constraint\-active sector adds no entropy deficit yet shapes the statistics: in a two\-sector example, forcing it to zero raises the value from 0 to 1 bit per round\. Dropping such a sector from the variable list can therefore overstate the key\.

- 6.4 [`meat-core/prop:no-averaging`](../claims/prop-no-averaging.tex): Unsoundness of averaging sectors ([PDF](../contract.pdf#nameddest=claim-meat-core/prop:no-averaging))

  **Non-normative summary.** Replacing the sectors of a declaration by one sector with averaged measurement operators can raise the value even where the averaged declaration reproduces the statistics, in the example from 0 to 1 bit per round\. Merging sectors is therefore no sound simplification\.

- 6.5 [`meat-core/prop:removal-compose`](../claims/prop-removal-compose.tex): Deleting a set of removable sectors ([PDF](../contract.pdf#nameddest=claim-meat-core/prop:removal-compose))

  **Non-normative summary.** Several removable sectors may be deleted together when every deleted sector's witness targets only sectors that stay\. The whole set may then be deleted without changing the value of the program or its attainment\.

- 6.6 [`meat-core/rem:target-conditions`](../claims/rem-target-conditions.tex): The two index conditions of the removal checklist ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:target-conditions))

  **Non-normative summary.** Without \(W2\) every state\-blind constraint\-active sector witnesses its own removal, and deleting it can overstate the value by a bit per round\. Distinct targets cost no removal in exact arithmetic: repeated targets merge into one witness certifying the same identities\.

- 6.7 [`meat-core/rem:witness-exactness`](../claims/rem-witness-exactness.tex): Exactness of the exhibited weights and states ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:witness-exactness))

  **Non-normative summary.** A witness is computed, not declared, so its weights and states can be made exact by construction; a naively summed weight vector can read 1 while its real sum exceeds 1\. The diagonal form of \(W4\) is one exact presentation of a state, not the only one binary64 admits\.

- 6.8 [`meat-core/rem:removal-general-format`](../claims/rem-removal-general-format.tex): Removal in the general format ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:removal-general-format))

  **Non-normative summary.** A party\-local entry makes clause \(d\) unsatisfiable, since the removal theorem excludes it; several measured factors leave the checklist no declared value to read, though the theorem can hold\. Either way no sector is flagged, so no set of sectors is deleted\.

- 6.9 [`meat-core/rem:removal-sets`](../claims/rem-removal-sets.tex): The set hypothesis of the composition rule ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:removal-sets))

  **Non-normative summary.** Per\-sector removal flags do not compose: two sectors can witness each other's removal, and deleting both raises the value by a bit per round\. The set hypothesis of [Proposition “Deleting a set of removable sectors”](../contract.pdf#nameddest=claim-meat-core/prop:removal-compose) is sufficient, not necessary, and is read on the recorded witnesses\.

- 6.10 [`meat-core/rem:classes`](../claims/rem-classes.tex): Retention and deletion of sectors ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:classes))

  **Non-normative summary.** Retaining every sector computes the value as defined; deleting one on an approximate match computes a restriction whose excess no function of a tolerance bounds, so a tolerance may only refuse a removal\. Dropping a constraint\-active sector and averaging sectors can both overstate the key\.


### 7 The Choi program

[Dependency view](group-07-the-choi-program.svg)

**Non-normative summary.** Every feasible state lives on the admissible Alice subspace, the support of the declared marginal \(all of Alice's system in untrusted\-source mode\), tensored with the measured system \([Lemma “The admissible Alice subspace”](../contract.pdf#nameddest=claim-meat-core/lem:admissible-alice-subspace)\)\. In trusted\-source mode every state with Alice's marginal is the image of a positive Choi operator on a support frame that need only contain the marginal's support, so no rank of the marginal is decided \([Lemma “Fixed\-marginal parametrisation on a support frame”](../contract.pdf#nameddest=claim-meat-core/lem:choi-marginal)\)\. [Theorem “The Choi program”](../contract.pdf#nameddest=claim-meat-core/thm:choi) rewrites the program exactly in sector Choi blocks, with one coupling constraint per Alice sector, and on a tight frame a homogeneous constraint row may drop its conjugation \([Proposition “Frame\-free constraint rows on a tight frame”](../contract.pdf#nameddest=claim-meat-core/prop:frame-free-rows)\); in untrusted\-source mode the parametrisation is the identity \([Definition “The program in untrusted\-source mode”](../contract.pdf#nameddest=claim-meat-core/def:untrusted-choi)\)\. The section's main result, [Lemma “Upper estimate of the value at any feasible point”](../contract.pdf#nameddest=claim-meat-core/lem:estimate), states that the objective at any exactly feasible point is at least h\_low: an upper estimate of the value, never a bound on it\.

- 7.1 [`meat-core/lem:admissible-alice-subspace`](../claims/lem-admissible-alice-subspace.tex): The admissible Alice subspace ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:admissible-alice-subspace))

  **Non-normative summary.** Every feasible state is supported in the admissible Alice subspace, the support of the declared marginal or all of Alice's system, tensored with the measured system; with no constraints the bound is tight\. The subspace depends on the marginal slot alone\.

- 7.2 [`meat-core/def:support-frame`](../claims/def-support-frame.tex): Support frame and declared isometry ([PDF](../contract.pdf#nameddest=claim-meat-core/def:support-frame))

  **Non-normative summary.** In trusted\-source mode a support frame is the range of an isometry ι from a Choi input register A₀ into A that contains the support of τ\_A, not necessarily equal to it\. Two exact constructions are named: the full frame, always available, and the diagonal frame, tight by construction\.

- 7.3 [`meat-core/lem:choi-marginal`](../claims/lem-choi-marginal.tex): Fixed-marginal parametrisation on a support frame ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:choi-marginal))

  **Non-normative summary.** On every support frame, W\_τ times its adjoint is τ\_A, and the Choi map carries the positive operators with identity input marginal onto the states with A\-marginal τ\_A\. It is injective on a tight frame, and only there unless the second system is trivial; being onto, it needs no rank decided\.

- 7.4 [`meat-core/lem:choi-factor`](../claims/lem-choi-factor.tex): Fixed-marginal parametrisation with any factor ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:choi-factor))

  **Non-normative summary.** Any factor W of Alice's marginal parametrises the fixed\-marginal states per Alice sector, and the objective reads her side only through her measurement sandwiched by W\. On the full frame these are the declared operators of an ensemble\-form declaration, so no rank is computed\.

- 7.5 [`meat-core/thm:choi`](../claims/thm-choi.tex): The Choi program ([PDF](../contract.pdf#nameddest=claim-meat-core/thm:choi))

  **Non-normative summary.** In trusted\-source mode the program is exactly a jointly convex minimisation over sector Choi blocks, with one coupling constraint per Alice sector and affine or conic rows\. Every support frame gives the value h\_low, since only surjectivity of the parametrisation enters it\.

- 7.6 [`meat-core/prop:frame-free-rows`](../claims/prop-frame-free-rows.tex): Frame-free constraint rows on a tight frame ([PDF](../contract.pdf#nameddest=claim-meat-core/prop:frame-free-rows))

  **Non-normative summary.** On a tight support frame a homogeneous row of the Choi program may drop its conjugation by W\_τ without changing the feasible set; on any frame the frame\-free row only restricts the set, so the infimum over it is at least h\_low\. The same holds per Alice sector and for party\-local rows\.

- 7.7 [`meat-core/rem:tightness-by-construction`](../claims/rem-tightness-by-construction.tex): Tightness read off the construction of the frame ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:tightness-by-construction))

  **Non-normative summary.** Deciding tightness of a given τ\_A is a rank decision on a computed spectrum; the diagonal frame exhibits it by construction, the full frame exhibits nothing\. Read at a positive window, the diagonality test would admit the frame\-free rows on a frame that is not tight\.

- 7.8 [`meat-core/rem:ordering`](../claims/rem-ordering.tex): Ordering convention and channel reading ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:ordering))

  **Non-normative summary.** In trusted\-source mode each Choi block J\_s is the Choi operator of a completely positive branch from A₀ to the sector, input factor first, and only the branches' sum preserves trace\. The reading is fixed only up to a unitary relabelling of the input, set by the declared isometry\.

- 7.9 [`meat-core/rem:basis-invariance`](../claims/rem-basis-invariance.tex): Invariance under the declared basis of the Choi input ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:basis-invariance))

  **Non-normative summary.** Within one support frame the declared isometry is fixed up to a unitary on A₀, which carries the Choi program onto itself, so the reported estimate, h\_lb and key length are invariant\. Across frames only h\_low and the sector report are frame\-free, and h\_lb ≤ h\_low holds in each frame\.

- 7.10 [`meat-core/def:untrusted-choi`](../claims/def-untrusted-choi.tex): The program in untrusted-source mode ([PDF](../contract.pdf#nameddest=claim-meat-core/def:untrusted-choi))

  **Non-normative summary.** In untrusted\-source mode the Choi step is the identity: the variables are the sector blocks of the state, coupled by the single scalar condition that their traces sum to one\. At d\_A = 1 this is the trusted\-mode Choi program\.

- 7.11 [`meat-core/lem:estimate`](../claims/lem-estimate.tex): Upper estimate of the value at any feasible point ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:estimate))

  **Non-normative summary.** The objective at any exactly feasible point, a state or the Choi operators of [Theorem “The Choi program”](../contract.pdf#nameddest=claim-meat-core/thm:choi) that parametrise one, is at least the value h\_low of the program\. It warrants the estimate every run reports, a solver diagnostic and never the lower bound a key length needs\.


### 8 Gradients and the limit of order one

[Dependency view](group-08-gradients-and-the-limit-of-order-one.svg)

**Non-normative summary.** The maximal branch support is the span of the pass\-class Kraus images of the admissible Alice subspace tensored with the sector; every branch operator the program forms lies in it, with equality at a positive definite Choi block \([Lemma “Properties of the maximal branch support”](../contract.pdf#nameddest=claim-meat-core/lem:branch-support)\)\. On the face of a singular operator the pinched trace power has a gradient in split form, with divided differences over the positive spectrum and pinched operators on the ambient space \([Theorem “Gradient of the pinched trace power on a face”](../contract.pdf#nameddest=claim-meat-core/thm:gradient)\)\. The full objective is differentiable along every feasible direction at a point of maximal support with positive probabilities \([Corollary “Gradient of the objective along feasible directions”](../contract.pdf#nameddest=claim-meat-core/cor:full-gradient)\); its branch values and pulled\-back gradient depend on the Kraus factors only through their Gram matrices, so exact factors may replace the square roots \([Lemma “Kraus freedom in the branch maps”](../contract.pdf#nameddest=claim-meat-core/lem:kraus-freedom)\)\. As the Rényi order tends to one the value converges to a blockwise relative\-entropy program when every acceptable distribution gives each key\-live value probability at least some p₀ \> 0 and some feasible state reproduces an acceptable distribution \([Theorem “Limit of the value as the Rényi order tends to one”](../contract.pdf#nameddest=claim-meat-core/thm:oracle)\), a validation reference and never a bound\.

- 8.1 [`meat-core/def:branch-support`](../claims/def-branch-support.tex): Maximal branch support ([PDF](../contract.pdf#nameddest=claim-meat-core/def:branch-support))

  **Non-normative summary.** The maximal branch support of a key\-live acceptance value and a sector is the span of the pass\-class Kraus images of the admissible Alice subspace tensored with the sector\. The side\-by\-side matrix of those Kraus operators depends on the declaration and the support frame alone\.

- 8.2 [`meat-core/lem:branch-support`](../claims/lem-branch-support.tex): Properties of the maximal branch support ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:branch-support))

  **Non-normative summary.** Every branch operator the program forms is supported in the maximal branch support, with equality at a positive definite Choi block; the support is the range of the stacked Kraus matrix\. It is always smaller than the ambient space and in general not invariant under the key pinching\.

- 8.3 [`meat-core/lem:dk`](../claims/lem-dk.tex): Divided-difference derivative of a matrix function ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:dk))

  **Non-normative summary.** At a Hermitian operator, a matrix function continuously differentiable around its spectrum has as derivative its divided\-difference kernel between spectral projectors, self\-adjoint under the trace pairing\. At trace level only the diagonal kernel survives\.

- 8.4 [`meat-core/thm:gradient`](../claims/thm-gradient.tex): Gradient of the pinched trace power on a face ([PDF](../contract.pdf#nameddest=claim-meat-core/thm:gradient))

  **Non-normative summary.** The pinched trace power is differentiable at a positive definite operator, and on the face of a singular one in split form: divided differences over the positive spectrum, pinched operators on the ambient space\. A one\-sided derivative is \+∞ only along a direction that enlarges the support\.

- 8.5 [`meat-core/cor:full-gradient`](../claims/cor-full-gradient.tex): Gradient of the objective along feasible directions ([PDF](../contract.pdf#nameddest=claim-meat-core/cor:full-gradient))

  **Non-normative summary.** At a point with positive probabilities and maximal branch supports, the objective of the Choi program is differentiable along every feasible direction, with an explicit gradient\. The point need only be positive semidefinite block by block, so the corollary applies at relaxed iterates\.

- 8.6 [`meat-core/lem:kraus-freedom`](../claims/lem-kraus-freedom.tex): Kraus freedom in the branch maps ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:kraus-freedom))

  **Non-normative summary.** Kraus factors with the same Gram matrices give branch operators related by a partial isometry commuting with the key pinching, so the trace power, deficit and pulled\-back gradient agree\. A subspace containing the support is the support once the compression to it is positive definite\.

- 8.7 [`meat-core/rem:directional-differentiability`](../claims/rem-directional-differentiability.tex): Scope of the directional differentiability of the objective ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:directional-differentiability))

  **Non-normative summary.** The objective of the Choi program is undefined off the positive cone and the sets [Corollary “Gradient of the objective along feasible directions”](../contract.pdf#nameddest=claim-meat-core/cor:full-gradient) quantifies over have empty interior, so only directional derivatives are well posed\. Even within the affine hull, a direction off the acceptance support can have one\-sided derivative −∞\.

- 8.8 [`meat-core/lem:b-derivative`](../claims/lem-b-derivative.tex): Derivative of the pinched trace power at order one ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:b-derivative))

  **Non-normative summary.** At Rényi order one the derivative of the pinched trace power of a subnormalised operator is minus ln 2 times its relative entropy to its pinching\. A jointly continuous majorant bounds the derivative just above order one, which carries the limit of order one through the infimum\.

- 8.9 [`meat-core/thm:oracle`](../claims/thm-oracle.tex): Limit of the value as the Rényi order tends to one ([PDF](../contract.pdf#nameddest=claim-meat-core/thm:oracle))

  **Non-normative summary.** If every acceptable distribution gives each key\-live value probability at least some p₀ \> 0 and some feasible state reproduces an acceptable distribution, the value tends, as α → 1, to a blockwise relative\-entropy program\. The limit is a validation reference and not a bound\.

- 8.10 [`meat-core/rem:oracle`](../claims/rem-oracle.tex): Validation against the order-one limit ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:oracle))

  **Non-normative summary.** The limit of [Theorem “Limit of the value as the Rényi order tends to one”](../contract.pdf#nameddest=claim-meat-core/thm:oracle) is a blockwise relative\-entropy program that checks an implementation as α → 1; it validates no finite\-α value and bounds nothing\. It is available only where every acceptable distribution is positive on the key\-live values\.


### 9 The dropped program

[Dependency view](group-09-the-dropped-program.svg)

**Non-normative summary.** A run may give up the entropy of chosen pairs of a key\-live acceptance value and a joint sector, setting their deficits to zero while keeping their variables, statistics and constraints \([Definition “Dropped set and dropped program”](../contract.pdf#nameddest=claim-meat-core/def:dropped)\)\. The resulting value bounds h\_low and the single\-round rate from below \([Proposition “The dropped program bounds the value from below”](../contract.pdf#nameddest=claim-meat-core/prop:drop-bound)\); it is attained when finite, and a fully dropped joint sector enters only through its statistics, with no matrix function \([Corollary “Convexity, gradient and limit of the dropped program”](../contract.pdf#nameddest=claim-meat-core/cor:drop-program)\)\. With every pair dropped the value is α/\(α−1\) times the minimal divergence between the accepted distributions and the statistics of the feasible set, a floor under h\_low that lies within the entropy ceiling of it, and a positive lower bound on it proves that no feasible state has an accepted distribution as its statistics \([Proposition “The minimal divergence as the value with every pair dropped”](../contract.pdf#nameddest=claim-meat-core/prop:minimal-divergence)\)\. On an Alice sector whose marginal has rank one, with default readouts and Alice holding the key, the deficit is linear with constants from declared numbers \([Lemma “Linear deficit on a rank\-one Alice sector”](../contract.pdf#nameddest=claim-meat-core/lem:rank-one-sector)\)\. The objective and the dropped objective, read on the whole cone, are positively homogeneous of degree one \([Lemma “Positive homogeneity of the objective”](../contract.pdf#nameddest=claim-meat-core/lem:objective-homogeneous)\)\.

- 9.1 [`meat-core/lem:rank-one-sector`](../claims/lem-rank-one-sector.tex): Linear deficit on a rank-one Alice sector ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:rank-one-sector))

  **Non-normative summary.** On an Alice sector of rank\-one marginal every feasible block is the fixed pure state times an operator on Q, and with default readouts and Alice holding the key its deficit is linear, with constants from declared numbers\. A uniform key bit gives one bit per unit of pass weight\.

- 9.2 [`meat-core/def:dropped`](../claims/def-dropped.tex): Dropped set and dropped program ([PDF](../contract.pdf#nameddest=claim-meat-core/def:dropped))

  **Non-normative summary.** A run may give up the entropy of chosen pairs of a key\-live acceptance value and a joint sector by setting their deficits to zero, keeping every variable, statistic and constraint\. The result is a program of its own; once any pair is dropped, its value is never reported as the undropped one\.

- 9.3 [`meat-core/prop:drop-bound`](../claims/prop-drop-bound.tex): The dropped program bounds the value from below ([PDF](../contract.pdf#nameddest=claim-meat-core/prop:drop-bound))

  **Non-normative summary.** Setting the deficits of a dropped set to zero can only lower the objective, so the dropped value lies between 0 and h\_low, hence below the single\-round rate, and never grows as the set grows\. Dropping only key\-inert pairs changes nothing\.

- 9.4 [`meat-core/cor:drop-program`](../claims/cor-drop-program.tex): Convexity, gradient and limit of the dropped program ([PDF](../contract.pdf#nameddest=claim-meat-core/cor:drop-program))

  **Non-normative summary.** The dropped objective is jointly convex and lower semicontinuous, its infimum attained when finite, and on a fully dropped joint sector it reads the block only through its statistics\. As the Rényi order tends to one the dropped value tends to the relative\-entropy program over the kept pairs\.

- 9.5 [`meat-core/prop:minimal-divergence`](../claims/prop-minimal-divergence.tex): The minimal divergence as the value with every pair dropped ([PDF](../contract.pdf#nameddest=claim-meat-core/prop:minimal-divergence))

  **Non-normative summary.** Dropping every pair leaves α/\(α−1\) times the minimal divergence between accepted distributions and feasible statistics, and h\_low lies between that and it plus log₂\(d\_Z\+1\) times the key\-live mass\. A positive lower bound proves that no feasible state has accepted statistics\.

- 9.6 [`meat-core/lem:objective-homogeneous`](../claims/lem-objective-homogeneous.tex): Positive homogeneity of the objective ([PDF](../contract.pdf#nameddest=claim-meat-core/lem:objective-homogeneous))

  **Non-normative summary.** Read on the whole cone, the objective, its Choi form and the dropped objective are positively homogeneous of degree one: scaling the acceptance vector and the state by c \> 0 scales the value by c\. This is what lets a first\-order bracket be formed without evaluating the objective\.


### 10 Key length

[Dependency view](group-10-key-length.svg)

**Non-normative summary.** The accumulated entropy feeds a fixed\-length post\-processing model with a fixed\-length error\-correction transcript, error verification and privacy amplification by ideal two\-universal hashing, every message public \([Definition “Fixed\-length post\-processing model”](../contract.pdf#nameddest=claim-meat-core/def:postprocessing-model)\)\. The section's main results are [Theorem “Secrecy of the key from the accumulated entropy”](../contract.pdf#nameddest=claim-meat-core/thm:keylength), an ε\_PA\-secret key of the stated length on the accepted state for a Rényi order in \(1, 2\), and [Corollary “Key length from any lower bound on the value”](../contract.pdf#nameddest=claim-meat-core/cor:keylength-bound), which lets any lower bound h ≤ h\_low take the place of h\_low through max\{0, h\} and is where every solver obtains its key length\. A run whose rounds follow statistics of feasible states passes the acceptance test with probability at most 2^\(−n D\_min\), D\_min the minimal divergence \([Proposition “The pass probability of devices the declared model admits”](../contract.pdf#nameddest=claim-meat-core/prop:model-pass-bound)\)\. ### 11 Perturbations of the declared measurement

[Dependency view](group-11-perturbations-of-the-declared-measurement.svg)

**Non-normative summary.** Declared data are binary64 numbers, and a declaration is exactly admissible when the conditions of [Definition “The protocol declaration as the MEAT core reads it”](../contract.pdf#nameddest=claim-meat-core/def:declaration) hold of those numbers themselves, among them operators exactly Hermitian, measurements and marginal exactly positive semidefinite, and completeness sums, formed in the declared order with no addition rounding, exactly the identity\. One might hope that two such declarations whose measurements on Q differ by at most ϵ have nearby rates; [Proposition “Instability of the rate under measurement perturbations”](../contract.pdf#nameddest=claim-meat-core/prop:optol-nobound) shows that they need not\. On data of fixed small dimensions their rate bounds can lie α/\(α−1\)·N bits per round apart, for every positive integer N ≤ 53 \+ log₂ϵ, which is up to 52 \([Remark “The representability ceiling”](../contract.pdf#nameddest=claim-meat-core/rem:representability-ceiling)\)\. The gap sits in the acceptance\-test penalty, can point either way and at the larger N is far above anything a key\-length claim could absorb \([Remark “Scope of the perturbation gap”](../contract.pdf#nameddest=claim-meat-core/rem:optol-direction)\)\. The engine therefore admits declared data only when they are exactly admissible \([Requirement “Exact admission of declared data”](../contract.pdf#nameddest=claim-meat-core/req:exact-admission)\), and the declared measurement model is itself a premise of every reported rate; where a reference of it is held, the first\-order bound is taken on the reference and the snap onto the lattice only steers the search, unless a number certified on the snapped declaration carries the key length, and no claim bounds the gap between the model and the device \([Remark “The declared measurement as a premise of the rate”](../contract.pdf#nameddest=claim-meat-core/rem:declared-measurement)\)\.

- 11.1 [`meat-core/prop:optol-nobound`](../claims/prop-optol-nobound.tex): Instability of the rate under measurement perturbations ([PDF](../contract.pdf#nameddest=claim-meat-core/prop:optol-nobound))

  **Non-normative summary.** Two exactly admissible measurements on Q within ϵ of each other can have rate bounds α/\(α−1\)·N bits per round apart, for every positive integer N ≤ 53 \+ log₂ϵ \(up to 52\)\. So closeness of the declared measurement cannot be relied on to carry a key\-rate claim to a nearby declaration\.

- 11.2 [`meat-core/rem:representability-ceiling`](../claims/rem-representability-ceiling.tex): The representability ceiling ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:representability-ceiling))

  **Non-normative summary.** The condition N ≤ 53 \+ log₂ϵ of [Proposition “Instability of the rate under measurement perturbations”](../contract.pdf#nameddest=claim-meat-core/prop:optol-nobound) is what exact admissibility forces on a two\-outcome binary64 family\. It caps N at 52, attained at ϵ = 1/2, and belongs to the number model, not to the map from the measurement to the rate\.

- 11.3 [`meat-core/rem:optol-direction`](../claims/rem-optol-direction.tex): Scope of the perturbation gap ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:optol-direction))

  **Non-normative summary.** The gap of [Proposition “Instability of the rate under measurement perturbations”](../contract.pdf#nameddest=claim-meat-core/prop:optol-nobound) involves no defect, lives in the acceptance\-test penalty and can point either way\. Among families of finite value the instance leaves an allowance of 53·α/\(α−1\) bits per round or more unrefuted; at a key rate below one bit no key\-length claim can rest on it\.

- 11.4 [`meat-core/rem:declared-measurement`](../claims/rem-declared-measurement.tex): The declared measurement as a premise of the rate ([PDF](../contract.pdf#nameddest=claim-meat-core/rem:declared-measurement))

  **Non-normative summary.** A tiny change of the declared measurement can move the key rate by many bits per round, so the model is a premise of the rate\. Where a handed reference's companion counts and the key length is formed on it, the snap only steers the search; nothing bounds model to device\.

## Part III: Frank-Wolfe first-order bound

**Non-normative summary.** The Frank\-Wolfe submodule supplies the first\-order lower bound on the core's value h\_low, and its main results are that bound, its forms for the dropped program and for the reference companion, and the key length from its certified form\. At a point of the Choi program where the relevant probabilities are positive and every key\-active branch operator has maximal support, the objective is differentiable along every feasible direction, and convexity turns its linearisation into a lower bound on h\_low once lower bounds on the linear minima over the acceptance set and over the feasible set are supplied \([Theorem “The estimate and the first\-order lower bound”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/thm:firstorder)\); the same holds for the dropped program, with maximal support asked only of the kept pairs \([Corollary “First\-order bound for the dropped program”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/cor:fo-dropped)\)\. The acceptance\-side minimum is computed exactly on the exact island, and the feasible\-side minimum is bounded from below in exact arithmetic from any multipliers, the solver's dual among them, with the rounding of the frame the rows are built with charged, so no bound trusts a solver's optimality \([Lemma “A lower bound on the feasible\-side minimum from any multipliers”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:feasible-side-dual)\)\. Iterates need only lie in a relaxed feasible set read at declared windows, both minima being taken over the exact sets, and reading the set at a window can only lower the value\. The theorem holds at any admissible points, wherever they came from, so a run that holds a reference of its snapped measurement forms the bound on the reference companion at the points its search on the snapped declaration produced and at those of a short search continued on the companion from them \([Corollary “The first\-order bound on the reference companion”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/cor:fo-reference)\)\. The resulting bound feeds the core's key\-length corollary; the objective at the returned point remains an estimate, and for the first\-order number the objective, the gradient and the data the engine computes from the declaration are evaluated in binary64 with no rounding\-error certificate\. At the run's final points the bound is formed again from enclosures of the gradient alone, the objective's homogeneity making a bracket the sum of its two lower bounds, every step from the declaration's data exact or rigorously enclosed; the best certified bracket gives the key length at the certified tier, a run whose companion certifies no point can be certified on its searched declaration under the snap premise instead, unless it declares strict\_snaps, and a run that certifies no point keeps its first\-order number with the reasons \([Lemma “The certified bracket from enclosures of the gradient”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:certified-bracket), [Corollary “Key length from the certified bracket”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/cor:certified-keylength)\)\.

**Non-normative summary.** The feasible\-side minimum is bounded from below by weak duality: the coupling condition fixes the total trace of every feasible point, so any multipliers, feasible for the dual or not, give a valid bound once the least eigenvalue of the residual operator is bounded from below \([Lemma “A lower bound on the feasible\-side minimum from any multipliers”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:feasible-side-dual)\)\. The bound reads no point a solver returned, and with a one\-dimensional coupling and no rows it is the minimum itself\. Rows built with a computed frame in place of the exact one cost a deduction linear in the row multipliers and in the frame's error, after which the bound holds over the exact set again\.

- 20.1 [`meat-core/frank-wolfe/lem:feasible-side-dual`](../frank-wolfe/claims/lem-feasible-side-dual.tex): A lower bound on the feasible-side minimum from any multipliers ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:feasible-side-dual))

  **Non-normative summary.** Any multipliers for the coupling condition and the declared rows give a lower bound on a linear form's minimum over the exact Choi feasible set, dual\-feasible or not, since the coupling fixes every feasible point's total trace\. Rows built from an inexact frame cost an explicit deduction\.


### 21 The certified bracket

[Dependency view](group-21-frank-wolfe-first-order-bound-the-certified-bracket.svg)

**Non-normative summary.** The objective is positively homogeneous of degree one, so at a point with positive definite blocks the gradient paired with the point is the objective there, and a bracket is the sum of its two lower bounds alone \([Lemma “The certified bracket from enclosures of the gradient”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:certified-bracket)\)\. Those bounds need only enclosures of the gradient: an entrywise one on the acceptance side, and on the feasible side a ball around an exact residual, the frame of the rows enclosed with it\. Over a reference companion known through enclosures, entrywise or, for an element of rank below its dimension, through an enclosed factor, one enclosure serves the companion itself where every element the gradient reads has its zero pattern and its rank fixed throughout \([Lemma “The certified bracket over a measured family known through enclosures”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:certified-bracket-enclosed)\)\. The best certified bracket gives the key length as any first\-order bound does \([Corollary “Key length from the certified bracket”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/cor:certified-keylength)\), on a companion for the protocol it declares \([Corollary “Key length on a reference companion from the certified bracket”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/cor:certified-keylength-reference)\)\.

- 21.1 [`meat-core/frank-wolfe/lem:certified-bracket`](../frank-wolfe/claims/lem-certified-bracket.tex): The certified bracket from enclosures of the gradient ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:certified-bracket))

  **Non-normative summary.** At a point with positive definite blocks and positive probabilities the gradient paired with the point is the objective, so the bracket is the sum of its two lower bounds and needs only enclosures of the gradient\.

- 21.2 [`meat-core/frank-wolfe/lem:certified-bracket-enclosed`](../frank-wolfe/claims/lem-certified-bracket-enclosed.tex): The certified bracket over a measured family known through enclosures ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:certified-bracket-enclosed))

  **Non-normative summary.** Over a reference companion whose measured families, of one or more replaced factors, are known through entrywise enclosures and on some blocks enclosed factors, one enclosure of the gradient serves the companion where every element the gradient reads has its zero pattern and rank fixed\.

- 21.3 [`meat-core/frank-wolfe/cor:certified-keylength`](../frank-wolfe/claims/cor-certified-keylength.tex): Key length from the certified bracket ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/cor:certified-keylength))

  **Non-normative summary.** The largest bracket formed by [Lemma “The certified bracket from enclosures of the gradient”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:certified-bracket) over finitely many points is a first\-order bound of [Theorem “The estimate and the first\-order lower bound”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/thm:firstorder), so it is at most the value of the declaration it is formed on and gives that declaration's fixed\-length key length exactly as h\_lb does\.

- 21.4 [`meat-core/frank-wolfe/cor:certified-keylength-reference`](../frank-wolfe/claims/cor-certified-keylength-reference.tex): Key length on a reference companion from the certified bracket ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/cor:certified-keylength-reference))

  **Non-normative summary.** On a reference companion, the best certified bracket, formed over its enclosed measured family as [Lemma “The certified bracket over a measured family known through enclosures”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:certified-bracket-enclosed) allows, gives the key length of the protocol whose declaration is the companion, as the first\-order bound on the companion does\.


### 22 The two minimisations and the arithmetic

[Dependency view](group-22-frank-wolfe-first-order-bound-the-two-minimisations-and-the-arithmetic.svg)

**Non-normative summary.** The assumption that a solver's feasible\-side return reached the minimum \([A\-LMO](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/ass:lmo)\) is superseded, and no claim rests on it: the feasible side is bounded by [Lemma “A lower bound on the feasible\-side minimum from any multipliers”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:feasible-side-dual)\. The acceptance\-side minimisation is a hypothesis of the bound that is discharged exactly on the exact island, for a singleton or a polytope acceptance set \([Remark “Exact minimisation on the acceptance side”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:acc-side)\)\. The remarks show that pairing over the acceptance support loses nothing and say what exact real arithmetic means for a printed bound, and which of its terms a run still computes in binary64\. A certified number rests on the claims, the declaration's modelling premises and the correctness of the implementation, and on no premise about arithmetic \([Remark “What a certified number rests on”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:certified-scope)\)\.

- 22.1 [`meat-core/frank-wolfe/ass:lmo`](../frank-wolfe/claims/ass-lmo.tex): Exact linear minimisation over the feasible set ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/ass:lmo))

  **Non-normative summary.** At every iterate a first\-order bound uses, the block list consumed from the oracle, any positivity repair included, puts the linear form of the gradient its bracket consumes at or below its minimum over the exact Choi feasible set\. No claim rests on it: [Lemma “A lower bound on the feasible\-side minimum from any multipliers”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/lem:feasible-side-dual) bounds that minimum instead\.

- 22.2 [`meat-core/frank-wolfe/rem:acc-side`](../frank-wolfe/claims/rem-acc-side.tex): Exact minimisation on the acceptance side ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:acc-side))

  **Non-normative summary.** For a singleton or a polytope acceptance set the acceptance\-side half of the linear minimisation is discharged by an exact minimisation, and a certified lower bound may replace the minimum, the bound staying valid\. An acceptance iterate formed exactly stays in the set by induction\.

- 22.3 [`meat-core/frank-wolfe/rem:pairing-on-acceptance-support`](../frank-wolfe/claims/rem-pairing-on-acceptance-support.tex): Pairing over the acceptance support ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:pairing-on-acceptance-support))

  **Non-normative summary.** Restricting the acceptance\-side pairing to the acceptance support loses nothing: a feasible direction vanishes outside it, and the oracle term is defined by that pairing\. The oracle return therefore need not be feasible, though in both admitted acceptance geometries it is\.

- 22.4 [`meat-core/frank-wolfe/rem:fo-arithmetic`](../frank-wolfe/claims/rem-fo-arithmetic.tex): Exact real arithmetic in the first-order bound ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:fo-arithmetic))

  **Non-normative summary.** Both linear minima are bounded exactly over the exact sets, but for the gradient as computed: the objective, the gradient and the maps and frame behind them are binary64, and a reference's centres move the measured family\. So a computed h\_lb may exceed h\_low, and the zero clamp repairs neither\.

- 22.5 [`meat-core/frank-wolfe/rem:certified-scope`](../frank-wolfe/claims/rem-certified-scope.tex): What a certified number rests on ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:certified-scope))

  **Non-normative summary.** A certified number rests on the claims, the modelling premises of its declaration and the correctness of the code, its ball\-arithmetic library included, and on no premise about arithmetic\. It does not reach data computed before the declaration; a receiver weight in floating point withholds it\.


### 23 The reported numbers and the runtime checks

[Dependency view](group-23-frank-wolfe-first-order-bound-the-reported-numbers-and-the-runtime-checks.svg)

**Non-normative summary.** These remarks give the mathematics behind the reporting rules\. A run reports its estimate and, where the hypotheses held, the first\-order bound, and withdrawal never weakens what the bound means \([Remark “Two reported numbers and one first\-order claim”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:fo-interface)\)\. The iterate checks decide the relaxed feasible set on the Choi factor only and serve the membership hypothesis and the estimate's premise \([Remark “What the iterate checks establish”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:fo-iterate-checks)\); maximal support is a rank equality read with one ruler \([Remark “Maximal support as a rank equality read with one ruler”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:fo-one-ruler)\); and the checks, computed in binary64, leave one\-sided exposures that no claim bounds\. A repaired oracle return is a step of the search and enters no bracket, a repaired iterate is a construction step, and a negative bound is clamped while a negative estimate is refused\.

- 23.1 [`meat-core/frank-wolfe/rem:fo-interface`](../frank-wolfe/claims/rem-fo-interface.tex): Two reported numbers and one first-order claim ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:fo-interface))

  **Non-normative summary.** A run reports its estimate always, and h\_lb only where the hypotheses of [Theorem “The estimate and the first\-order lower bound”](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/thm:firstorder) held, membership of the consumed point in the acceptance set times the relaxed set among them\. No hypothesis is read of the solver, and withdrawal never weakens what h\_lb means\.

- 23.2 [`meat-core/frank-wolfe/rem:fo-iterate-checks`](../frank-wolfe/claims/rem-fo-iterate-checks.tex): What the iterate checks establish ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:fo-iterate-checks))

  **Non-normative summary.** The three iterate checks decide every condition of the relaxed feasible set, all of them on the J factor; the acceptance factor holds by construction\. They serve the membership hypothesis and the estimate's premise; no check of a solver's return would serve the bound\.

- 23.3 [`meat-core/frank-wolfe/rem:fo-returned-point`](../frank-wolfe/claims/rem-fo-returned-point.tex): What the measurement of the returned point establishes ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:fo-returned-point))

  **Non-normative summary.** The point a run returns is checked once more, on its J factor only, so a pass establishes that factor of the estimate's premise and a failure leaves the premise unestablished\. - 23.4 [`meat-core/frank-wolfe/rem:fo-one-ruler`](../frank-wolfe/claims/rem-fo-one-ruler.tex): Maximal support as a rank equality read with one ruler ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:fo-one-ruler))

  **Non-normative summary.** \(H\-SUPP\) is equivalent to rank X = dim W, never to positivity of X on its ambient space, whose spectrum always contains 0\.   **Non-normative summary.** An iterate with positive weight on a point of positive definite Choi blocks and an acceptance vector positive on the acceptance support meets \(H\-SUPP\) and \(H\-POS\)'s first clause; such a point exists if the declared rows admit one\. No optimiser is fixed: a run without such a component may lack h\_lb\.

- 23.6 [`meat-core/frank-wolfe/rem:fo-check-exposures`](../frank-wolfe/claims/rem-fo-check-exposures.tex): One-sided exposures of the runtime checks ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:fo-check-exposures))

  **Non-normative summary.** The rank comparison for \(H\-SUPP\) and the three iterate checks are computed in binary64 and leave three one\-sided exposures, two on the unsafe side, that no claim of this module bounds\. - 23.7 [`meat-core/frank-wolfe/rem:fo-oracle-repair`](../frank-wolfe/claims/rem-fo-oracle-repair.tex): A repaired oracle return as a step of the search ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:fo-oracle-repair))

  **Non-normative summary.** Repairs are permitted on computed objects and never on declared data\. A repaired oracle return feeds only the search and a recorded diagnostic, and its record bounds nothing: a window on the block bounds no error on a pairing whose gradient can grow without limit\.

- 23.9 [`meat-core/frank-wolfe/rem:fo-negative-values`](../frank-wolfe/claims/rem-fo-negative-values.tex): Opposite treatment of a negative bound and a negative estimate ([PDF](../contract.pdf#nameddest=claim-meat-core/frank-wolfe/rem:fo-negative-values))
